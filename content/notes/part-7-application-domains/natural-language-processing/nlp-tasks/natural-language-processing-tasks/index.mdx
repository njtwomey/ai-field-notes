<Definition>
An **NLP task** is a precisely posed problem on text, defined by its input, its output and how outputs are scored.
The tasks in this chapter differ mainly in the shape of the output: one label for a document, one of three labels for
a pair of sentences, a sentence in another language, a shorter text, or an answer to a question. Each was once solved
by its own specialised model and is now usually solved by fine-tuning or prompting a pretrained transformer.
</Definition>

## What it is for

These tasks are what deployed language technology does: filter spam and route tickets, translate pages, condense
reports, and answer questions over documents. They are also the benchmarks on which
<Gloss name="language-model">language models</Gloss> are compared, so their definitions fix what "understanding" means
in practice. Knowing how a task is framed tells a practitioner which model output to train, which loss to use and which
metric to report <Cite id="jurafsky2025" />.

## Main ideas

**One label per document.** <NoteLink to="text-classification" /> assigns a document a label from a fixed set, such as a
sentiment or a topic. Classical models are linear in <NoteLink to="bag-of-words">bag-of-words</NoteLink> counts.
Fine-tuned encoders place a softmax layer on a transformer's output <Cite id="devlin2019" />, and large language models
classify without training by scoring each label.

**A label for a pair of sentences.** <NoteLink to="natural-language-inference" /> labels a premise and hypothesis as
entailment, contradiction or neutral. Entailment models are reused for zero-shot classification and for checking
whether generated text is faithful to its source.

**Text in, text out.** <NoteLink to="machine-translation" /> maps a sentence to its translation. Statistical
translation factorised the problem with a noisy-channel model and word alignments; neural translation models the
target sentence directly with an attentional encoder–decoder. <NoteLink to="summarisation" /> shortens a text while
keeping its main content, by selecting source sentences (extractive) or by generating new text (abstractive).
Faithfulness to the source is a separate requirement that fluent summaries often fail.

**Find the answer, then return it.** <NoteLink to="question-answering" /> returns an answer to a natural-language
question. Extractive question answering predicts the answer as a span of a given passage. Open-domain question
answering must also find the evidence, by retrieval or from knowledge stored in a language model's parameters.

## How the notes fit together

Start with <NoteLink to="text-classification" />, the simplest output. Natural language inference is a classification
of sentence pairs and comes next. Machine translation introduces the encoder–decoder used by summarisation, so read it
before summarisation. Question answering combines span prediction with retrieval and can be read last.
