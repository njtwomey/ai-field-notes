<Definition>
**Graph-based recommendation** represents logged interactions as a bipartite graph, with users and items as nodes and
each interaction as an edge. A graph neural network then computes each node's embedding from its neighbours, and the
neighbours' neighbours, so that a user's vector reflects the items they used and the other users of those items.
Recommendations are the items whose embeddings score highest against the user's.
</Definition>

## What it is for

Matrix factorisation learns each user's vector from that user's own interactions, and relies on shared items only
through the loss. A graph model uses the connections directly: two users who never shared an item are linked if their
items were used by the same third user. These multi-hop paths help most for users and items with few interactions. The
same machinery extends to richer graphs with several node types, such as users, dishes and restaurants, and to
web-scale graphs with billions of edges <Cite id="he2020lightgcn" />.

## Main ideas

**Collaborative filtering as paths on a graph.** <NoteLink to="graph-collaborative-filtering" /> shows that each layer
of message passing updates a node from its neighbours, so $K$ layers encode paths of length $K$. Neural graph
collaborative filtering (NGCF) applies weight matrices and non-linearities at each layer, as in a standard graph
convolutional network <Cite id="wang2019ngcf" />.

**Less machinery works better.** <NoteLink to="lightgcn" /> removes the weight matrices and non-linearities. It
propagates embeddings by repeated multiplication with the normalised adjacency matrix and averages the layers. Only the
layer-0 embeddings are trained. On standard benchmarks this simpler model outperforms NGCF.

**Propagation itself carries the signal.** <NoteLink to="untrained-graph-propagation" /> propagates random features over
a small social network, by an untrained graph convolutional network or by powers of the normalised adjacency matrix.
The result already separates the network's two communities, because repeated averaging acts as a low-pass filter that
keeps community-level structure. This explains why LightGCN needs no learned transformations.

**A production case.** <NoteLink to="uber-eats-graph-learning" /> embeds users, dishes and restaurants with a
<Gloss name="graphsage" /> variant on per-city order graphs. A max-margin loss ranks often-ordered dishes above rarely
ordered ones, and embedding similarities become features of the downstream ranking model.
