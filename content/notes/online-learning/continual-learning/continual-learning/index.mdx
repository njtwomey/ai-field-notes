<Definition>
In **continual learning** a model with parameters $\thetavec$ is trained on a sequence of tasks $k = 1, \dots, K$, each
with its own data distribution $\Dcal_k$. While training on task $k$ it sees data from $\Dcal_k$ only, apart from what
it may store in a small memory. After task $k$ it is evaluated on all tasks $1, \dots, k$. **Catastrophic forgetting**
is the loss of performance on earlier tasks caused by training on later ones <Cite id="mccloskey1989" />
<Cite id="parisi2019" />.
</Definition>

## Notation

$L_k(\thetavec) = \expect_{(\xvec, y) \sim \Dcal_k}\ell(\thetavec; \xvec, y)$ is the risk on task $k$, and $\thetavec_k$
the parameters after training on task $k$. The target is a small total risk $\sum_{j \le k}L_j(\thetavec_k)$ at every
stage, the risk that joint training on all tasks would minimise if their data were available together.

## Forgetting in a linear model

Forgetting needs no deep network. Take <NoteLink to="linear-regression">linear regression</NoteLink>,
$\ell(\wvec; \xvec, y) = (y - \wvec^\top\xvec)^2$, trained by <NoteLink to="gradient-descent">gradient
descent</NoteLink> to convergence on each task in turn.

**Gradient descent stays in the span of the inputs.** The <NoteLink to="gradient">gradient</NoteLink> on task $k$ is a
combination of that task's inputs $\xvec$. Starting from $\wvec_{k-1}$, every step adds a vector in the
<NoteLink to="rank-and-null-space">row space</NoteLink> of the task's data matrix $\Xmat_k$. The limit is the solution
of task $k$ closest to the starting point:

$$
\wvec_k = \wvec_{k-1} + \Xmat_k^{+}(\yvec_k - \Xmat_k\wvec_{k-1}),
$$

where $\Xmat_k^{+}$ is the pseudo-inverse. The change $\wvec_k - \wvec_{k-1}$ lies in the row space of $\Xmat_k$.

**Forgetting requires overlapping row spaces.** Task $j < k$ is affected only through the component of this change in
the row space of $\Xmat_j$. If every input of task $j$ is orthogonal to every input of task $k$, then
$\Xmat_j(\wvec_k - \wvec_{k-1}) = \zeros$ and task $j$ is untouched. If the row spaces overlap and the tasks disagree on
those directions, task $j$'s loss rises.

**Worked example.** In $\reals^2$, task A has one example $\xvec = (1, 0)$, $y = 1$. From $\wvec = \zeros$ gradient
descent reaches $\wvec_A = (1, 0)$, with loss 0. Task B has $\xvec = (1, 1)$, $y = 0$. The residual at $\wvec_A$ is
$-1$, and the step is $\xvec(-1)/\norm{\xvec}^2 = (-0.5, -0.5)$, giving $\wvec_B = (0.5, -0.5)$. Task B's loss is 0;
task A's has risen from 0 to $(0.5 - 1)^2 = 0.25$. Had task B's input been $(0, 1)$, orthogonal to task A's, task A
would have kept loss 0. A weight vector with loss 0 on both tasks exists, $(1, -1)$; sequential training does not find
it, because nothing in task B's objective refers to task A.

Deep networks show the same mechanism in a stronger form. Their tasks share features in every layer, so the overlap
is large, and training to convergence on task $k$ moves the weights far <Cite id="french1999" />.

## The stability–plasticity dilemma

A learner that never changes its weights never forgets and never learns. One that follows each new task freely
learns fast and forgets. Every continual learning method chooses a point between these, and methods are compared by
how much they retain for a given ability to learn <Cite id="parisi2019" />. Three families exist.

- **<NoteLink to="regularisation">Regularisation</NoteLink>** penalises changes to weights that mattered for old tasks,
  or to the old outputs: <NoteLink to="regularisation-based-continual-learning" />, such as elastic weight consolidation
  <Cite id="kirkpatrick2017" />.
- **Replay** keeps a small memory of old examples, or a generator of them, and trains on them alongside the new task:
  <NoteLink to="replay-and-architectural-methods" />, including gradient episodic memory <Cite id="lopezpaz2017" />.
- **Architecture** gives each task its own parameters, or grows the network, so that new tasks cannot overwrite old
  ones: also in <NoteLink to="replay-and-architectural-methods" />.

## Three scenarios

The difficulty depends on what the model is told at test time. Van de Ven and Tolias distinguish three scenarios
<Cite id="vandeven2019" />, illustrated on split <Gloss name="mnist" />, which divides the ten digits into five tasks of
two digits each.

| Scenario | At test time the model must | Split MNIST example |
| --- | --- | --- |
| Task-incremental | solve a task whose identity it is told | given the task, tell its two digits apart |
| Domain-incremental | solve the current kind of problem without the task identity | say whether a digit is the first or second of its pair |
| Class-incremental | infer the task as well as solve it | name the digit, out of all ten |

Task-incremental learning can use a separate output head per task and is the easiest. Class-incremental learning is
the hardest: the model must compare classes that were never trained together. In van de Ven and Tolias's experiments,
regularisation methods retained most of their accuracy in the task-incremental scenario but fell to near the accuracy
of plain fine-tuning in the class-incremental one, while replay kept high accuracy in all three
<Cite id="vandeven2019" />.

## Relation to online learning

Continual learning and <NoteLink to="online-learning">online learning</NoteLink> both train on a non-stationary
sequence, but they measure different things.

- Online learning measures cumulative loss on the sequence as it arrives, against a comparator. When the data drift,
  forgetting the old concept is the goal: <NoteLink to="concept-drift-adaptation" /> is about forgetting at the right
  rate.
- Continual learning measures performance on all earlier tasks after training, because they remain relevant. Retention
  is the goal. <NoteLink to="evaluating-continual-learners" /> defines the metrics.

A single stream can need both: a recurring concept is one that should be retained while it is absent and recovered
when it returns. Forward transfer between tasks, the other half of lifelong learning, is covered in
<NoteLink to="lifelong-and-continual-transfer" />.

## Assumptions

- Task boundaries are usually known during training, so a method can consolidate at the end of each task. Task-free
  continual learning drops this assumption.
- Memory and compute are bounded. Storing all data and retraining jointly is excluded, and is the upper baseline that
  methods are compared with.
- Tasks share structure. Without it, the only way to keep old tasks is to keep separate parameters.

## Pitfalls

- **Reporting only the final task.** A model can look strong on the last task while having forgotten the others.
  Report the whole accuracy matrix.
- **Scenario mismatch.** Results in the task-incremental scenario do not transfer to class-incremental use. State the
  scenario, and whether task identity is available at test time.
- **Confusing forgetting with interference at test time.** In class-incremental learning, much of the drop is a bias of
  the output layer towards recent classes rather than lost features. Classifying by distances to class means of stored
  exemplars, as iCaRL does, avoids part of this bias <Cite id="rebuffi2017" />.
