<Definition>
**Interpretability** is the degree to which a person can understand the cause of a model's prediction
<Cite id="doshivelez2017" />. An **explanation** is an object, such as a set of feature weights, a highlighted region, a
rule or a nearby example, that conveys part of that cause. Interpretability methods either restrict the model so that
its parameters are the explanation (**intrinsic**), or compute an explanation from a trained model that is otherwise
opaque (**post-hoc**).
</Definition>

## Two distinctions

Interpretability methods are classified along two independent axes <Cite id="lipton2018mythos" /> <Cite id="molnar2022" />.

- **Intrinsic or post-hoc.** An intrinsically interpretable model, such as a sparse linear model, a short rule list or
  a <NoteLink to="generalised-additive-model">generalised additive model</NoteLink>, has a structure a person can read
  directly. A post-hoc method takes a fitted model $f$ and produces an explanation of $f$ without changing it. A post-hoc
  explanation is a second model of the first, so it can be wrong about $f$.
- **Global or local.** A global explanation describes $f$ over the whole input space: which features matter on
  average, the shape of each feature's effect. A local explanation describes $f$ near one input $\xvec$: why this
  applicant was refused, which pixels made this image a "dog".

A third distinction is **model-specific** against **model-agnostic**. Gradient-based attributions need a
differentiable $f$. TreeSHAP needs a tree ensemble. LIME and counterfactual search need only the ability to query
$f(\xvec)$.

## Taxonomy

| method | intrinsic or post-hoc | scope | needs | explanation |
| --- | --- | --- | --- | --- |
| sparse linear model, <NoteLink to="lasso">lasso</NoteLink> | intrinsic | global | nothing extra | coefficients |
| <NoteLink to="generalised-additive-model">GAM</NoteLink>, <NoteLink to="explainable-boosting-machines">EBM</NoteLink> | intrinsic | global and local | nothing extra | one shape function per feature |
| <NoteLink to="decision-tree">decision tree</NoteLink>, rule list | intrinsic | global and local | nothing extra | the path or rule that fired |
| MIL pooling for time series (MILLET) | intrinsic | local | a pooling layer | a score per time point |
| permutation importance | post-hoc | global | queries of $f$ | drop in accuracy per feature |
| partial dependence, ICE | post-hoc | global | queries of $f$ | average or per-example effect curve |
| saliency, integrated gradients | post-hoc | local | gradients of $f$ | a score per input feature |
| LIME | post-hoc | local | queries of $f$ | a local sparse linear model |
| SHAP, <NoteLink to="shap-values-for-trees">TreeSHAP</NoteLink> | post-hoc | local, averaged to global | queries of $f$, or the trees | Shapley value per feature |
| counterfactual explanation | post-hoc | local | queries or gradients of $f$ | the smallest change that flips the output |
| TCAV | post-hoc | global per class | gradients, concept examples | sensitivity to a human concept |

## What an explanation is for

Explanations serve different users. A model developer uses them to find bugs, such as a classifier that relies on a
watermark. A regulator or affected person uses them to contest a decision. A scientist uses them to generate
hypotheses. Doshi-Velez and Kim separate three ways of testing whether an explanation helps: with the real task and
real users (application-grounded), with simplified tasks and lay users (human-grounded), and with a formal proxy and no
users (functionally grounded) <Cite id="doshivelez2017" />.

## Intrinsic against post-hoc

Rudin argues that for high-stakes decisions on structured data an interpretable model should be preferred to a black
box with post-hoc explanations <Cite id="rudin2019" />. Her argument has three steps. On tabular data with meaningful
features, interpretable models often match black boxes in accuracy. A post-hoc explanation that agreed with the black
box everywhere would itself be an interpretable model of equal accuracy, so an explanation that is needed must
disagree with the model somewhere. That disagreement is invisible to the user. The counter-position is that on raw
signals, such as images, audio and text, the most accurate models are deep networks with no readable structure, and
post-hoc methods are the only option.

## Pitfalls

- **Explanations are not causes in the world.** An attribution explains the model's output, not the process that
  generated the data. A feature can dominate an attribution because it is correlated with the real cause.
- **Plausible is not faithful.** An explanation that looks sensible to a person can be unrelated to the model's
  computation. Sanity checks have found saliency methods whose maps barely change when the model's weights are
  randomised <Cite id="adebayo2018" />.
- **Explanations can be gamed.** LIME and KernelSHAP query the model on perturbed inputs that lie off the data
  distribution. A classifier can detect such inputs and behave innocuously on them while discriminating on real
  inputs, so that its explanations hide the bias <Cite id="slack2020" />.
