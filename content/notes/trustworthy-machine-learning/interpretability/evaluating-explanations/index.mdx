<Definition>
An explanation of a model $f$ is **faithful** if it accurately reflects the reasoning by which $f$ produced its output,
and **plausible** if it is convincing to a person <Cite id="jacovi2020" />. Evaluating an explanation method means
measuring its faithfulness, its plausibility or its usefulness for a task. Faithfulness is measured without human
judgement, by changing the input or the model according to the explanation and checking that the model responds as the
explanation predicts.
</Definition>

## Why faithfulness and plausibility differ

A person judging a <NoteLink to="feature-attribution-methods">saliency map</NoteLink> sees whether the highlighted region matches what the person would have looked at. This
measures plausibility: agreement with human reasoning. The model may use a different region, such as a watermark or a
background texture. An explanation that showed the watermark would be faithful and implausible. An explanation that
showed the object would be plausible and unfaithful. Jacovi and Goldberg argue that the two must be evaluated
separately, and that user studies measure plausibility, not faithfulness <Cite id="jacovi2020" />. Doshi-Velez and Kim
distinguish application-grounded evaluations with real users and tasks, human-grounded evaluations with simplified
tasks, and functionally grounded evaluations with formal proxies and no users <Cite id="doshivelez2017" />. The measures
below are functionally grounded.

## Perturbation curves

Let an attribution method rank the $d$ features of $\xvec$ from most to least important. If the ranking is faithful,
removing the features in that order, **most relevant first** (MoRF), should make $f$ drop fast. Let $\xvec^{(k)}$ be
$\xvec$ with its top $k$ features removed, for example set to a baseline value.

- **AOPC.** Samek et al. average the drop over the first $L$ removal steps and over inputs
  <Cite id="samek2017" />:
  $\mathrm{AOPC} = \frac{1}{L + 1}\Big\langle \sum_{k=0}^{L} f(\xvec^{(0)}) - f(\xvec^{(k)}) \Big\rangle_{p(\xvec)}$. A larger AOPC means
  a more faithful ranking.
- **Deletion and insertion.** Petsiuk et al. plot the class probability as pixels are deleted in order of importance
  and take the area under the curve; a low deletion area is good <Cite id="petsiuk2018" />. The insertion curve starts
  from a blurred image and inserts pixels in order of importance; a high insertion area is good.
- **AOPCR.** An AOPC value depends on the model and the data. Subtracting the AOPC of random orderings gives a score
  that is zero for an uninformative ranking and negative for a ranking worse than random. For <Gloss name="mil">multiple instance
  learning</Gloss> and time series, Early et al. define
  $\mathrm{AOPCR} = \frac{1}{3}\sum_{r=1}^{3}\big(\mathrm{AOPC}(\text{ranking}) - \mathrm{AOPC}(\text{random ranking } r)\big)$ <Cite id="early2022" /> <Cite id="early2024" />.

## Worked example

A linear model $f(\xvec) = \wvec^\top\xvec$ with $\wvec = (3, -1, 2, 0.5)$ and input $\xvec = (1, 2, 1, 2)$ has
contributions $w_j x_j = (3, -2, 2, 1)$ and $f(\xvec) = 4$. Removing a feature sets it to $0$. An exact attribution
ranks the features $1, 3, 4, 2$.

- **MoRF drops.** Removing feature 1 leaves $1$, a drop of $3$. Removing feature 3 as well leaves $-1$, a drop of $5$.
  Removing feature 4 leaves $-2$, a drop of $6$. With $t = 4$ features and $t - 1 = 3$ steps, the AOPC in the form
  $\frac{1}{t - 1}\sum_{j=1}^{t-1}\big(f(\xvec) - f(\xvec^{(j)})\big)$ is $(3 + 5 + 6)/3 = 4.67$.
- **Random orderings.** Each feature is among the first $j$ removed with probability $j/4$, so the expected drop after
  $j$ removals is $\frac{j}{4}\sum_i w_i x_i = j$. The expected random AOPC is $(1 + 2 + 3)/3 = 2$.
- **AOPCR.** $4.67 - 2 = 2.67$. An attribution that ranked feature 2 first would score lower, because removing a
  feature with a negative contribution raises $f$.

## Remove and retrain

Deleting features produces inputs unlike any training input. A drop in $f$ may then reflect the distribution shift, not
the loss of information. **ROAR** (remove and retrain) replaces the top fraction of features ranked by the method with
an uninformative value in every training and test image, retrains the model from scratch, and measures the drop in test
accuracy <Cite id="hooker2019" />. If the removed features carried the information the model used, accuracy falls more
than when the same fraction is removed at random. Under ROAR, Hooker et al. found plain <NoteLink to="gradient">gradients</NoteLink>, integrated gradients
and guided backpropagation on image classifiers no better than a random ranking, while the ensembling methods
SmoothGrad-Squared and VarGrad were far better <Cite id="hooker2019" />. ROAR costs one training run per method and
removal fraction.

## Sanity checks

An explanation that describes the model must change when the model changes. Adebayo et al. propose two <NoteLink to="permutation-tests">randomisation
tests</NoteLink> <Cite id="adebayo2018" />.

- **Model parameter randomisation.** Re-initialise the network's weights, from the top layer downwards, and compare the
  explanations before and after. Explanations that barely change cannot be describing what the trained weights compute.
- **Data randomisation.** Train the same architecture on randomly permuted labels, which forces it to memorise, and
  compare its explanations with those of the model trained on true labels.

Plain gradients and Grad-CAM changed substantially under both tests. Guided backpropagation and guided Grad-CAM produced
nearly the same maps for the trained and the randomised network: they behave like edge detectors of the input rather
than descriptions of the model <Cite id="adebayo2018" />. A related check is **input invariance**: adding a constant to
every input, and compensating in the first layer's bias, leaves the model's function unchanged, yet changes gradient ×
input and integrated gradients with a zero baseline <Cite id="kindermans2019" />. Integrated gradients with the baseline
shifted by the same constant is unaffected, since its completeness is relative to the baseline
<Cite id="sundararajan2017" />.

## Ground-truth benchmarks

On synthetic data the discriminative features are known, so an explanation can be scored against them as a ranking
problem. The <NoteLink to="millet">MILLET</NoteLink> evaluation of time-series classifiers injects class signatures at known positions in a synthetic
data set, WebTraffic, and scores each ranking of time points by the <Gloss name="ndcg">normalised discounted cumulative gain</Gloss> of its first
$n$ positions, where $n$ is the number of discriminatory time points <Cite id="early2024" />:

$$
\mathrm{NDCG@}n = \frac{1}{\mathrm{IDCG}}\sum_{j=1}^{n}\frac{\mathrm{rel}(o_j)}{\log_2(j + 1)}, \qquad \mathrm{IDCG} = \sum_{j=1}^{n}\frac{1}{\log_2(j + 1)},
$$

with $\mathrm{rel}(o_j) = 1$ if the $j$-th ranked time point is discriminatory and $0$ otherwise. Scoring the same
methods with both a faithfulness measure and a ground-truth measure is informative: on those long series, <Gloss name="shap" /> with a
limited sampling budget had a negative AOPCR, worse than a random ranking, while the model's own time-point scores
ranked well on both measures <Cite id="early2024" />. Ground truth tests whether a method finds the features that
generated the label, which can differ from the features the model uses.

## Pitfalls

- **Removal is not neutral.** Setting a pixel to black or a word to a mask token introduces a new signal. Different
  removal values give different curves.
- **One number hides trade-offs.** A sparse explanation scores well on AOPC, because a few removed features collapse the
  prediction, and can score poorly against ground truth that covers a whole region.
- **Metrics disagree.** Faithfulness measures rank methods differently. Report several, with the random-ranking
  reference.
