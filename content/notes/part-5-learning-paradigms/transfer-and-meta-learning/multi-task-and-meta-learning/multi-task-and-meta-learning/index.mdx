<Definition>
**Multi-task learning** trains one model on several related tasks at once, so that each task borrows statistical
strength from the others. **Meta-learning** trains on a distribution of tasks so that a new task from the same
distribution can be learnt from a few examples. Both treat a task, not an example, as the unit of data, and both learn
what the tasks have in common: shared features, a shared prior, or a shared initialisation.
</Definition>

## What it is for

Many problems come as families of small related tasks: a recommender per user, a classifier per hospital, a controller
per robot, a vocabulary of new classes each with five labelled images. Training each task alone wastes the shared
structure and overfits. Training one model across tasks reduces the data each task needs. Few-shot
<NoteLink to="image-classification">image classification</NoteLink>, personalisation, and fast adaptation of robot
policies are the standard applications.

## Main ideas

**Share parameters across tasks.** <NoteLink to="multi-task-learning" /> uses common layers with one output head per
task (hard sharing), or separate parameters coupled by a penalty (soft sharing) <Cite id="caruana1997" />. The shared
part is fitted to all the tasks' data. Tasks that conflict can hurt each other, which makes grouping and gradient
balancing part of the method.

**Share a prior.** <NoteLink to="hierarchical-bayesian-transfer" /> gives every task's parameters a common Gaussian
prior, learns the prior's mean and covariance from source tasks, and uses it for a new task. A new task starts at the
source mean and moves towards its own estimate as its data grow, the same shrinkage as in
<NoteLink to="hierarchical-models">hierarchical models</NoteLink>.

**Learn an initialisation.** <NoteLink to="meta-learning" /> covers MAML, which learns parameters from which one or a
few gradient steps fit any new task, by differentiating through those steps. First-order MAML and Reptile drop the
second derivatives, which contribute little <Cite id="finn2017maml" />. Meta-learning methods are surveyed in
<Cite id="hospedales2021" />.

**Learn a metric.** <NoteLink to="metric-based-few-shot-learning" /> trains an embedding on many small episodes so that
a new class is recognised by distance to a few examples. Prototypical networks classify by the nearest class mean, and
with squared Euclidean distance this is a linear classifier.

**Evaluate on episodes.** <NoteLink to="few-shot-learning-evaluation" /> tests on episodes of $N$ unseen classes with
$K$ labelled examples each, and reports mean accuracy with a confidence interval over hundreds of episodes. A
pretrained network with a linear classifier on top is the baseline that meta-learning methods must beat.

## Prerequisites and next steps

The notes assume <NoteLink to="transfer-learning">transfer learning</NoteLink>, <NoteLink to="gradient-descent">gradient
descent</NoteLink> and, for MAML, <NoteLink to="automatic-differentiation">automatic differentiation</NoteLink> through
an optimisation step. The hierarchical note needs <NoteLink to="bayesian-linear-regression" />.

Shared representations connect this topic to <NoteLink to="representation-learning">representation learning</NoteLink>:
a large pretrained encoder fine-tuned per task is now the most common form of transfer across tasks.
<Gloss name="llm">Large language models</Gloss> learn new tasks from a few examples in the prompt, without gradient
steps, which is covered under <NoteLink to="in-context-learning">in-context learning</NoteLink>.
<NoteLink to="active-transfer-learning" /> and <NoteLink to="lifelong-and-continual-transfer">lifelong and continual
transfer</NoteLink> extend transfer across tasks to label selection and to tasks that arrive in sequence.
