<Definition>
Question answering (QA) maps a question $q$, and possibly a context, to an answer. In **extractive** QA the context is a
passage $c = (c_1, \dots, c_n)$ of $n$ tokens and the answer is a contiguous span $c_{i:j}$ with $1 \le i \le j \le n$.
In **open-domain** QA no passage is given: the system must find evidence in a large collection or answer from knowledge
stored in its parameters <Cite id="jurafsky2025" />.
</Definition>

## Intuition

Restricting the answer to a span of the passage turns an open-ended generation problem into a choice among at most
$n(n+1)/2$ candidates. A model then only has to score, for every token, how likely it is to start the answer and how
likely it is to end it.

## Extractive QA

The Stanford Question Answering Dataset (SQuAD) made span extraction the standard reading-comprehension task. Crowd
workers wrote more than 100,000 questions about paragraphs from over 500 Wikipedia articles, each answered by a span of
its paragraph. A <NoteLink to="logistic-regression">logistic regression</NoteLink> baseline reached 51.0% F1 against 86.8% for humans <Cite id="rajpurkar2016" />.
SQuAD 2.0 added over 50,000 unanswerable questions written to resemble answerable ones, so that a system must also
decide when the passage contains no answer <Cite id="rajpurkar2018" />.

### Span scoring

<Gloss name="bert" /> packs the question and passage into one input, `[CLS]` $q$ `[SEP]` $c$ `[SEP]`, and produces a final hidden vector
$\tvec_i \in \reals^{H}$ for every passage token <Cite id="devlin2019" />. Fine-tuning adds only two vectors, a start
vector $\svec \in \reals^{H}$ and an end vector $\evec \in \reals^{H}$. Each token gets a start logit and an end
logit,

$$
s_i = \svec^\top \tvec_i, \qquad e_j = \evec^\top \tvec_j,
$$

and each is normalised over the passage by a <NoteLink to="softmax-and-log-sum-exp">softmax</NoteLink>:

$$
P_{\text{start}}(i) = \frac{\exp s_i}{\sum_{k} \exp s_k}, \qquad P_{\text{end}}(j) = \frac{\exp e_j}{\sum_{k} \exp e_k}.
$$

**Training.** For a gold span $(i^\star, j^\star)$, the loss is the sum of the two cross-entropies,
$-\log P_{\text{start}}(i^\star) - \log P_{\text{end}}(j^\star)$. This is the <NoteLink to="cross-entropy-and-perplexity">negative log-likelihood</NoteLink> of the span under a
model in which the start and end are independent given the encoded input, $P(i, j) = P_{\text{start}}(i)\,
P_{\text{end}}(j)$. The encoder sees both question and passage through self-attention, so the two distributions are
dependent through $\tvec$, but the output layer treats them as independent.

**Inference.** Under the independent model, the most probable valid span maximises
$\log P_{\text{start}}(i) + \log P_{\text{end}}(j)$ subject to $i \le j$. Expanding the logarithms,

$$
\log P_{\text{start}}(i) + \log P_{\text{end}}(j) = s_i + e_j - \log \sum_k \exp s_k - \log \sum_k \exp e_k.
$$

The two log-normalisers do not depend on $(i, j)$, so they drop out of the argmax:

$$
(\hat i, \hat j) = \argmax_{i \le j \le i + L - 1} \; (s_i + e_j),
$$

where $L$ is a maximum answer length in tokens. Taking the start argmax and the end argmax separately can give $j < i$,
which is not a span, so the constraint must be imposed jointly. The search is $O(nL)$ by enumeration, or $O(n)$ by
sweeping $j$ from left to right while keeping the maximum of $s_i$ over the window $j - L + 1 \le i \le j$.

**Unanswerable questions.** For SQuAD 2.0, BERT treats the `[CLS]` position as a "no answer" span with score
$s_{\text{null}} = s_{\text{CLS}} + e_{\text{CLS}}$. It predicts an answer only when the best non-null span score
exceeds $s_{\text{null}} + \tau$, with the threshold $\tau$ chosen on development data <Cite id="devlin2019" />.

### Worked example

A passage has five tokens with start logits $\svec = (0.5, 2.0, 0.1, 2.3, -1.0)$ and end logits
$(-0.5, 0.3, 2.2, 1.6, 0.0)$, indexed from 0. The maximum answer length is $L = 3$.

- **Separate argmaxes fail.** The start argmax is token 3 and the end argmax is token 2, and $j < i$.
- **Joint search.** The best valid spans are $(1, 2)$ with score $2.0 + 2.2 = 4.2$, $(3, 3)$ with $2.3 + 1.6 = 3.9$ and
  $(1, 3)$ with $2.0 + 1.6 = 3.6$. The prediction is tokens 1 to 2.
- **Probability.** $P_{\text{start}}(1) = 0.361$ and $P_{\text{end}}(2) = 0.533$, so the span has probability $0.192$.
  If $(1, 2)$ is the gold span, the training loss is $-\ln 0.361 - \ln 0.533 = 1.649$ nats.

## Evaluation

Extractive QA is scored by exact match and token-level F1 against one or more gold answers, after normalising case,
punctuation and articles; see <NoteLink to="squad-exact-match-and-f1">SQuAD exact match and F1</NoteLink>
<Cite id="rajpurkar2016" />.

## Open-domain QA

Open-domain QA has no given passage. A **retriever-reader** system first retrieves passages from a collection, then
applies an extractive reader to each and returns the best-scoring span. DrQA used <Gloss name="tf-idf" /> retrieval over Wikipedia with
a neural reader <Cite id="chen2017" />. The retrieval step is not covered here.

<Gloss name="llm">Large language models</Gloss> also answer **closed-book**, generating the answer from knowledge stored in their parameters.
<Gloss name="gpt-3" /> answered TriviaQA questions few-shot with no retrieval <Cite id="brown2020" />. Closed-book answers cannot cite a
source and are wrong more often on rare facts; see <NoteLink to="hallucination-and-faithfulness">hallucination and
faithfulness</NoteLink>. <NoteLink to="retrieval-augmented-generation">Retrieval-augmented generation</NoteLink> combines
the two: retrieved passages are placed in the generator's input, and the answer is generated rather than extracted.

## Pitfalls

- **Lexical overlap shortcuts.** Many SQuAD questions reuse words from the sentence containing the answer, so a model
  can match surface forms without understanding. SQuAD 2.0's unanswerable questions were written to defeat this
  <Cite id="rajpurkar2018" />.
- **Long passages.** Encoders have a maximum input length. Longer passages are split into overlapping windows, and the
  best span across windows is returned.
- **One span may not be the answer.** Questions whose answer is a list, a yes or no, or a number computed from the text
  are outside span extraction.
