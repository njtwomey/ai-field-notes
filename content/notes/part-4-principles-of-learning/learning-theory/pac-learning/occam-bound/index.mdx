<Definition>
Let $\Hcal$ be a countable class of classifiers and $\pi$ a weighting of $\Hcal$ with $\pi(h) \ge 0$ and
$\sum_{h \in \Hcal}\pi(h) \le 1$, chosen before the sample $S$ of $m$ independent examples is drawn. The **Occam bound**
states that, with probability at least $1 - \delta$, every $h \in \Hcal$ satisfies

$$
R(h) \le \hat R_S(h) + \sqrt{\frac{\ln(1/\pi(h)) + \ln(1/\delta)}{2m}}.
$$

In the exact form, $R(h)$ is at most the <NoteLink to="test-set-bounds">binomial tail inversion</NoteLink> of
$h$'s training errors at confidence $\delta\pi(h)$ <Cite id="langford2005" /> <Cite id="blumer1987" />.
</Definition>

## Intuition

The finite-class bound splits the failure probability $\delta$ equally: each of $\abs{\Hcal}$ hypotheses may fail with
probability $\delta/\abs{\Hcal}$, and every hypothesis's bound contains the term $\ln\abs{\Hcal}$. A countable class has
no equal share to give. The Occam bound gives each hypothesis its own share $\delta\pi(h)$. Hypotheses with large weight
get a large share and a tight bound; hypotheses with small weight get a loose one. The shares still add up to at most
$\delta$.

The weights $\pi$ express which hypotheses the analyst expects before seeing the data. They are often called a "prior",
but the bound holds whether or not the data follow any Bayesian model <Cite id="langford2005" />.

The Occam bound is the third move of the <NoteLink to="statistical-learning-theory">recipe for a generalisation
bound</NoteLink>, making a concentration bound uniform, done with a weighted union bound.

The name comes from Occam's razor. If short descriptions get large weights, a hypothesis that is simple to describe and
fits the data well comes with a better guarantee than a complex one with the same training error
<Cite id="blumer1987" />.

## Derivation



1. **One hypothesis, its own confidence.** Fix $h$ with $\pi(h) > 0$. Because $h$ is fixed before the sample is drawn,
   the one-sided <NoteLink to="hoeffdings-inequality">Hoeffding bound</NoteLink> at confidence $\delta\pi(h)$ gives

$$
\prob\paren{R(h) > \hat R_S(h) + \sqrt{\frac{\ln(1/(\delta\pi(h)))}{2m}}} \le \delta\pi(h).
$$

2. **Weighted union bound.** By the <NoteLink to="union-bound">union bound</NoteLink>, the probability that the bound
   fails for at least one $h$ is at most $\sum_h \delta\pi(h) \le \delta$. Hypotheses with $\pi(h) = 0$ get the trivial
   bound $R(h) \le 1$ and contribute nothing.
3. **Reading the bound.** $\ln(1/(\delta\pi(h))) = \ln(1/\pi(h)) + \ln(1/\delta)$, which gives the bound in the
   definition. It holds for all $h$ simultaneously, so it also holds for any $h$ chosen after looking at the data.

The same steps with the exact binomial tail in place of Hoeffding's inequality give the exact form. With the
relative-entropy relaxation they give
$\operatorname{kl}(\hat R_S(h) \,\|\, R(h)) \le (\ln(1/\pi(h)) + \ln(1/\delta))/m$, where $\operatorname{kl}$ is the
<Gloss name="kl">Kullback–Leibler divergence</Gloss> between Bernoulli laws. In the realisable case, the argument of
<NoteLink to="realisable-and-agnostic-learning">realisable learning</NoteLink> with confidence $\delta\pi(h)$ gives,
for every $h$ with zero training error,

$$
R(h) \le \frac{\ln(1/\pi(h)) + \ln(1/\delta)}{m}.
$$

A uniform weighting $\pi(h) = 1/\abs{\Hcal}$ on a finite class recovers the finite-class bound.

## Description length as capacity

A weighting can be built from a code. Fix, before seeing data, a prefix-free binary code that describes each hypothesis
$h$ by a string $\sigma(h)$ of $\abs{\sigma(h)}$ bits; no code word is the start of another. The Kraft inequality
states that $\sum_h 2^{-\abs{\sigma(h)}} \le 1$ for any prefix-free code
(<NoteLink to="source-coding-theorem">source coding theorem</NoteLink>). The weights
$\pi(h) = 2^{-\abs{\sigma(h)}}$ are therefore valid, and

$$
\ln\frac{1}{\pi(h)} = \abs{\sigma(h)}\ln 2.
$$

The capacity term of the Occam bound is the description length of $h$ in nats. The bound holds for every $h$ the code
can describe, and its capacity term depends only on the hypothesis returned, not on how many others the learner could
have returned.

Three later ideas extend this one.

- **Structural risk minimisation.** Choosing the $h$ that minimises the right side of the Occam bound trades training
  error against description length, and the bound still holds for the choice
  (<NoteLink to="structural-risk-minimisation">structural risk minimisation</NoteLink>).
- **Minimum description length.** Coding the training labels given $h$ adds a second part to the code. The total
  code length is a model-selection criterion
  (<NoteLink to="minimum-description-length">minimum description length</NoteLink>).
- **PAC-Bayes.** Replacing the single hypothesis by a distribution $Q$ over hypotheses replaces $\ln(1/\pi(h))$ by the
  Kullback–Leibler divergence $\KL(Q \,\|\, \pi)$ (<NoteLink to="pac-bayes-bounds">PAC-Bayes bounds</NoteLink>).

Blumer, Ehrenfeucht, Haussler and Warmuth stated the learning-theoretic form: an algorithm that returns a consistent
hypothesis of size at most $(ns)^c m^\alpha$ is a <Gloss name="pac" /> learner, where $n$ is the input dimension, $s$
the size of the target, $c \ge 0$ and $0 \le \alpha < 1$. Such an algorithm is called an **Occam algorithm**
<Cite id="blumer1987" /> <Cite id="kearns1994book" />. The compression $m^\alpha$ with $\alpha < 1$ makes the
description length grow more slowly than the sample, so the bound $(\ln(1/\pi(h)) + \ln(1/\delta))/m$ goes to zero.

## Worked example

Binary <NoteLink to="decision-tree">decision trees</NoteLink> on 20 binary features are coded in pre-order. Every node
costs 1 bit to say whether it is a leaf, an internal node costs 5 more bits to name its feature ($2^5 = 32 \ge 20$), and
a leaf costs 1 more bit for its label. A tree with $s$ internal nodes has $s + 1$ leaves, so its code has

$$
(2s + 1) + 5s + (s + 1) = 8s + 2 \text{ bits}.
$$

The pre-order leaf/internal bits determine where the code word ends, so the code is prefix-free and Kraft's
inequality holds. Take $m = 10{,}000$ training examples and $\delta = 0.05$, so $\ln(1/\delta) = 3.00$. The table
gives four trees of increasing size with illustrative training errors.

| Internal nodes $s$ | Bits | $\ln(1/\pi)$ | Hoeffding width | Training error | Hoeffding bound | Relative-entropy bound |
| --- | --- | --- | --- | --- | --- | --- |
| 10 | 82 | 56.8 | 0.055 | 0.10 | 0.155 | 0.136 |
| 100 | 802 | 555.9 | 0.167 | 0.05 | 0.217 | 0.157 |
| 1,000 | 8,002 | 5,547 | 0.527 | 0.01 | 0.537 | 0.456 |
| 5,000 | 40,002 | 27,727 | 1.18 | 0.00 | vacuous | 0.938 |

1. **The width.** For $s = 10$, $\sqrt{(56.8 + 3.0)/20{,}000} = 0.055$, so a 10% training error certifies a true error
   below 15.5%.
2. **Simplicity against fit.** The 100-node tree fits better (5% training error) and still has the worse Hoeffding
   bound, 21.7% against 15.5%. The relative-entropy bound, which is tighter at small training errors, narrows the gap
   to 15.7% against 13.6%.
3. **<NoteLink to="non-vacuous-generalisation-bounds">Vacuous bounds</NoteLink>.** The 5,000-node tree has nearly one
   leaf for every two examples and zero training error. Its Hoeffding bound exceeds 1, and its relative-entropy bound of
   0.94 is no better than guessing.
4. **Sample size.** For the 100-node tree to have a Hoeffding width of 0.05, the sample must grow to
   $m = 558.9/(2 \times 0.05^2) = 111{,}780$ examples.

## Pitfalls

- **The weights must be fixed before the data.** A code or prior designed after seeing the sample, for example one that
  gives the learned tree a short code word, voids the bound.
- **The bound measures the code, not the hypothesis.** The same tree can be cheap under one code and expensive under
  another. A poor code gives loose bounds even for simple hypotheses.
- **Many equivalent descriptions waste weight.** When several code words describe the same function, each gets its own
  share of $\delta$, and the function's bound uses only one of them. Summing the weights of all code words for a
  function gives a tighter bound.
