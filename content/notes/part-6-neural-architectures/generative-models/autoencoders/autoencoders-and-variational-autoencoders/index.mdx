<Definition>
An **autoencoder** is a pair of networks: an encoder $f$ that maps an input $\xvec$ to a code $\zvec$, and a decoder $g$
that maps the code back to a reconstruction $\hat\xvec = g(\zvec)$. It is trained to make $\hat\xvec$ close to $\xvec$
while some constraint stops it from copying. A **variational autoencoder** (VAE) makes the code a
<NoteLink to="random-variable">random variable</NoteLink> with a prior, which turns the autoencoder into a generative
model trained by maximising a lower bound on the data's log-likelihood <Cite id="kingma2019" />.
</Definition>

## What it is for

Autoencoders learn compact representations without labels. The code can be used for
<NoteLink to="dimensionality-reduction">dimensionality reduction</NoteLink>, visualisation, denoising,
<NoteLink to="anomaly-detection">anomaly detection</NoteLink> by reconstruction error, and as features for other models
<Cite id="bengio2013" />. VAEs add generation: sampling a code from the prior and decoding it gives a new example, and
moving through the code space interpolates between examples. Discrete autoencoders, VQ-VAE and RQ-VAE, turn images,
audio or items into sequences of tokens. Those tokens feed autoregressive and <Gloss name="diffusion-model">diffusion
models</Gloss>, as in <NoteLink to="latent-diffusion" />, and serve as semantic IDs for items in
<NoteLink to="generative-retrieval-for-recommendation">generative retrieval for recommendation</NoteLink>.

## Main ideas

**A bottleneck forces a summary.** The plain <NoteLink to="autoencoder" /> reconstructs its input through a narrow
code. With a linear encoder and decoder and squared error, the optimal code spans the top principal subspace of the
data, so the linear autoencoder recovers <NoteLink to="principal-component-analysis" />. Nonlinear networks learn
curved low-dimensional structure.

**Regularisation replaces the bottleneck.** <NoteLink to="regularised-autoencoders" /> learn useful codes even when the
code is as wide as the input. A denoising autoencoder reconstructs clean inputs from corrupted ones, a sparse
autoencoder penalises active code units, and a contractive autoencoder penalises the encoder's Jacobian.

**A probabilistic code makes a generative model.** The <NoteLink to="variational-autoencoder" /> pairs a decoder
$p_{\thetavec}(\xvec \mid \zvec)$ and a prior $p(\zvec)$ with an encoder $q_{\phivec}(\zvec \mid \xvec)$. It maximises
the evidence lower bound: expected reconstruction log-likelihood minus
$\KL(q_{\phivec}(\zvec \mid \xvec) \,\|\, p(\zvec))$. The reparameterisation trick gives low-variance gradients through
the sampled code.

**Variants change the condition or the weight.** A <NoteLink to="conditional-variational-autoencoder" /> conditions
the prior, encoder and decoder on side information such as a label, and generates varied outputs for one condition.
A <NoteLink to="beta-variational-autoencoder" /> multiplies the KL term by $\beta$; with $\beta > 1$ codes carry less
information and tend to align single coordinates with single factors of variation, at a cost in reconstruction.

**Discrete codes from a codebook.** A <NoteLink to="vector-quantised-variational-autoencoder" /> replaces the
continuous code by the nearest vector in a learned codebook, passes gradients through the lookup with the
straight-through estimator, and fits a prior over code indices afterwards. A
<NoteLink to="residual-quantised-variational-autoencoder" /> quantises in several stages, each coding what the earlier
ones left, so a code is a coarse-to-fine sequence of indices.
