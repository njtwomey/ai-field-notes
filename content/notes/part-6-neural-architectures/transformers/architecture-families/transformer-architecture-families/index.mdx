<Definition>
A **transformer architecture family** is defined by how its attention is masked and how its stacks are arranged.
Bidirectional attention lets every token see every other; causal attention lets each token see only those before it. An
encoder-only model uses bidirectional attention throughout, a decoder-only model causal attention throughout, an
<Gloss name="seq2seq">encoder-decoder</Gloss> model one stack of each joined by cross-attention, and a prefix language
model a single stack whose mask is bidirectional over a prefix and causal after it <Cite id="raffel2020" />.
</Definition>

## What it is for

The original transformer was an encoder-decoder for translation. Its parts were then separated and recombined, and the
choice of family decides what a model can do. An encoder-only model produces one vector per input token and suits
classification, tagging and retrieval embeddings, but it cannot generate text. A decoder-only model generates text and
turns any task into a continuation, which is why nearly all <Gloss name="llm">large language models</Gloss> use it. An
encoder-decoder model suits tasks with a distinct input and output, such as translation and summarisation. Controlled
comparisons find that the best family depends on the training objective and on whether the model is used zero-shot or
after fine-tuning <Cite id="wang2022architecture" />.

## Main ideas

**The mask defines the family.** All four families use the same blocks of attention and feed-forward layers. What
differs is which positions each token may attend to, and that in turn decides which training losses are possible. A
causal mask allows a next-token loss at every position; a bidirectional mask needs a denoising objective, since each
token could otherwise see its own target.

**Encoders denoise.** <NoteLink to="encoder-only-transformers" /> map $n$ tokens to $n$ contextual vectors. They are
pre-trained by <NoteLink to="masked-language-modelling" /> or by ELECTRA's replaced-token detection, and fine-tuned
with a small head for each task.

**Decoders continue text.** <NoteLink to="decoder-only-transformers" /> read a prompt and write its continuation with
the same weights. Every position gives a training signal, past keys and values are cached at generation time, and a
single model handles many tasks through prompting.

**Encoder-decoders separate reading from writing.** <NoteLink to="encoder-decoder-transformers" /> read the input with
a bidirectional encoder and write the output with a causal decoder that cross-attends to it. With $L$ layers per stack
the model has the parameters of a $2L$-layer decoder but roughly the compute per token of an $L$-layer one. T5 and BART
are examples.

**One stack, several masks.** <NoteLink to="prefix-language-models-and-unified-models" /> use a mask that is
bidirectional over the first $P$ tokens and causal after them. Varying $P$ turns one set of weights into an encoder, a
decoder or an encoder-decoder; UniLM and UL2 train on a mixture of such masks.
