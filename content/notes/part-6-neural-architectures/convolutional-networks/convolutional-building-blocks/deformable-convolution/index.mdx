<Definition>
A **deformable convolution** is a convolutional layer whose kernel taps read the input at positions shifted by learned,
input-dependent offsets. At output position $\pvec_0$, tap $n$ of a $k \times k$ kernel reads the input at
$\pvec_0 + \pvec_n + \Delta\pvec_n$, where $\pvec_n$ is the tap's place on the regular grid and
$\Delta\pvec_n \in \reals^2$ is predicted at $\pvec_0$ by a second convolution over the same input. Fractional positions
are read by bilinear interpolation, so the output is differentiable in the offsets and the offset branch trains by
backpropagation from the task loss alone. The modulated form multiplies each tap by a learned scalar $m_n \in [0, 1]$.
</Definition>

## Intuition

A <NoteLink to="convolutional-layer">convolutional layer</NoteLink> reads a fixed square of pixels around every output
position. The square has the same shape at every position and for every input. Objects do not: a car seen at 10 metres
and at 100 metres differs in size by a factor of ten, a pedestrian may be upright or bent, and a road curves. A
$3 \times 3$ kernel centred on a thin diagonal line reads three pixels on the line and six off it.

The tools of <NoteLink to="receptive-field-and-dilated-convolution">receptive field and dilated convolution</NoteLink>
change the size of the square but not its shape, and they change it the same way everywhere. Dilation $d$ spreads the
taps $d$ pixels apart in every layer, for every image and at every position. A network that must see large and small
objects in one image has to fix one compromise for both.

A deformable convolution makes the sampling grid a function of the input. A small convolution looks at the
neighbourhood of each output position and predicts where each of the nine taps should read. On a large object the taps
spread out; on a small one they close in; along a curved structure they bend with it. The weights stay shared across
positions, as in an ordinary layer, so the layer still has $k^2 C C'$ kernel weights. What changes is where the weights
read.

Dai et al. measured the spread with the **effective dilation**, the mean distance between adjacent sampling positions of
one kernel. In the last stage of a ResNet-101 detector on PASCAL VOC, it averaged $5.3$ on small objects and $8.4$ on
large ones in the same layer <Cite id="dai2017deformable" />. No label told the network to do this; the offsets were
learned from the detection loss.

## Details

### The layer

Write the regular grid of a $3 \times 3$ kernel as
$\mathcal{R} = \set{(-1, -1), (-1, 0), \dots, (1, 1)}$, positions as (row, column) pairs, and the $N = 9$ grid points as
$\pvec_1, \dots, \pvec_N$. For one input channel $x$ and kernel weights $w_n$, an ordinary layer computes

$$
y(\pvec_0) = \sum_{n=1}^{N} w_n\, x(\pvec_0 + \pvec_n).
$$

A deformable layer adds an offset $\Delta\pvec_n$ to every tap <Cite id="dai2017deformable" />:

$$
y(\pvec_0) = \sum_{n=1}^{N} w_n\, x(\pvec_0 + \pvec_n + \Delta\pvec_n).
$$

With $C$ input and $C'$ output channels, output channel $c'$ sums
$w_{c', c, n}\, x_c(\pvec_0 + \pvec_n + \Delta\pvec_n)$ over channels $c$ and taps $n$. In the original layer the
offsets of one tap are shared by all input channels, so each output position has $N$ offsets, $2N$ numbers.

Dilation is a special case. Fixed offsets $\Delta\pvec_n = (d - 1)\, \pvec_n$, the same at every position, move tap $n$
to $\pvec_0 + d\, \pvec_n$, the grid of dilation $d$. Fixed offsets that scale or rotate the grid are special cases too.
A deformable layer can represent all of them, and a different one at every position.

### Bilinear sampling

The offsets are real numbers, so $\pvec_0 + \pvec_n + \Delta\pvec_n$ usually falls between pixels. The layer reads it by
bilinear interpolation:

$$
x(\pvec) = \sum_{\qvec} G(\qvec, \pvec)\, x(\qvec), \qquad
G(\qvec, \pvec) = g(q_1, p_1)\, g(q_2, p_2), \qquad g(a, b) = \max(0,\ 1 - \abs{a - b}),
$$

where $\qvec$ runs over the integer pixel positions <Cite id="dai2017deformable" />. The kernel $G$ is non-zero only
for the four pixels around $\pvec$. Write $\pvec = (r + \alpha,\ c + \beta)$ with integers $r, c$ and fractions
$\alpha, \beta \in [0, 1)$, and $x_{ij}$ for the pixel at $(r + i,\ c + j)$. Then

$$
x(\pvec) = (1 - \alpha)(1 - \beta)\, x_{00} + (1 - \alpha)\beta\, x_{01} + \alpha(1 - \beta)\, x_{10} + \alpha\beta\, x_{11}.
$$

The four weights are non-negative and sum to 1. At an integer position one weight is 1 and the sample is the pixel.
Positions outside the image read zeros, as zero padding does.

### The offset branch

The offsets come from an ordinary convolution applied to the same input. It has the kernel size and dilation of the
deformable layer and $2N$ output channels: one $\Delta$row and one $\Delta$column per tap, at every output position
<Cite id="dai2017deformable" />. For a $3 \times 3$ layer on $C = 256$ channels, the offset branch has
$9 \cdot 256 \cdot 18 = 41{,}472$ weights, against $9 \cdot 256 \cdot 256 = 589{,}824$ in a $256 \to 256$ main layer, 7%
more.

The offset branch is initialised with zero weights. At the start of training every offset is zero and the layer is the
ordinary convolution it replaces, so a pretrained backbone keeps its behaviour while the offsets learn. Nothing
supervises the offsets directly; they move only when moving them lowers the task loss.

The offset branch is itself a convolution, so a shifted input shifts the offset field by the same amount. The whole
layer therefore keeps the translation equivariance of an ordinary layer, away from the borders and at stride 1.

### Gradients through the sampling

Bilinear interpolation is a piecewise-linear function of the position, so the output has a gradient with respect to
each offset. For tap $n$,

$$
\frac{\partial y(\pvec_0)}{\partial \Delta\pvec_n} = w_n\, \nabla x(\pvec), \qquad \pvec = \pvec_0 + \pvec_n + \Delta\pvec_n.
$$

Differentiating the four-term formula in $\alpha$ and $\beta$ gives the two components of $\nabla x$:

$$
\frac{\partial x}{\partial \alpha} = (1 - \beta)(x_{10} - x_{00}) + \beta\,(x_{11} - x_{01}), \qquad
\frac{\partial x}{\partial \beta} = (1 - \alpha)(x_{01} - x_{00}) + \alpha\,(x_{11} - x_{10}).
$$

Each component is a weighted difference of neighbouring pixels across the cell. The gradient pushes a tap towards
brighter or darker pixels, whichever lowers the loss given the sign of $w_n$ and of the gradient arriving from above.
The chain rule carries $\partial \ell / \partial \Delta\pvec_n$ on into the weights of the offset branch. The gradient
sees only the $2 \times 2$ cell that contains the sample, so offsets move by local steps.

### Modulation

Deformable ConvNets v2 multiplies each tap by a modulation scalar $m_n \in [0, 1]$ <Cite id="zhu2019deformable" />:

$$
y(\pvec_0) = \sum_{n=1}^{N} w_n\, m_n\, x(\pvec_0 + \pvec_n + \Delta\pvec_n).
$$

The offset branch has $3N$ output channels. The first $2N$ are the offsets and the last $N$ pass through a sigmoid to
give the $m_n$. With zero-initialised weights, training starts at $\Delta\pvec_n = 0$ and $m_n = 0.5$. Offsets move
where a tap reads; modulation decides how much it counts, so a tap that lands on background can be switched off. DCNv2
put modulated deformable layers in all $3 \times 3$ layers of the conv3 to conv5 stages of a
<NoteLink to="classic-convolutional-network-architectures">ResNet-50</NoteLink>, 12 layers, where DCNv1 had used 3, and
trained the offset branches with one tenth of the main <Gloss name="learning-rate">learning rate</Gloss>
<Cite id="zhu2019deformable" />.

### From sampled points to attention

Modulated deformable convolution is a <NoteLink to="sliding-window-and-sparse-attention">sparse attention</NoteLink>.
Each output position aggregates $N$ input values at learned positions with learned weights $m_n$. Two lines of work made
the link explicit.

- **DCNv3** in the InternImage backbone splits the channels into $G$ groups with their own offsets, shares one
  projection across the taps of a group in the manner of a <NoteLink to="depthwise-and-grouped-convolution">depthwise
  separable convolution</NoteLink>, and normalises the modulation scalars by a softmax over the $N$ taps
  <Cite id="wang2023internimage" />. InternImage scaled this operator to a backbone of about one billion parameters.
  **DCNv4** drops the softmax and reorganises memory access, for a <NoteLink to="multilayer-perceptron">forward
  pass</NoteLink> more than three times faster than DCNv3 <Cite id="xiong2024dcnv4" />.
- **Deformable attention** in Deformable DETR lets each query in a transformer detector attend to a few sampled points
  around a reference position, with offsets and weights predicted from the query <Cite id="zhu2021deformabledetr" />.
  Its cost is linear in the number of points instead of quadratic in the number of pixels; see
  <NoteLink to="object-detection" />.

<NoteLink to="scaled-dot-product-attention">Dense attention</NoteLink> sits at the other end: every query weights every
key, and positions are not sampled at all.

### Relation to spatial transformers

A spatial transformer network predicts one transformation per image, such as an affine map with six parameters, and
resamples the whole feature map with it by the same bilinear interpolation <Cite id="jaderberg2015stn" />. It
normalises a global pose: it rotates a tilted digit upright before classification. A deformable convolution predicts a
local, free-form warp: nine offsets at every position of every layer. It adapts to many objects of different shapes in
one image, which a single global warp cannot.

### Cost and practice

The arithmetic overhead is small: the offset branch costs about $2N / C'$ of the main layer, and each sample adds four
multiply-adds per channel. The runtime overhead is larger. Each tap gathers four pixels at data-dependent addresses,
which defeats the contiguous memory access that tuned convolution kernels rely on, and the layer needs its own kernel
in every framework. DCNv4 is mostly about this memory traffic <Cite id="xiong2024dcnv4" />. Practitioners replace the
$3 \times 3$ layers of the last stages of a detection or segmentation backbone, where objects vary most in scale, and
leave the early layers plain <Cite id="dai2017deformable" /> <Cite id="zhu2019deformable" />. In PyTorch the operator is
`torchvision.ops.deform_conv2d`.

## Worked example

Take a $5 \times 5$ image with a bright anti-diagonal ridge, rows and columns indexed from 0, and a $3 \times 3$ mean
kernel, $w_n = 1/9$, at the centre $\pvec_0 = (2, 2)$:

$$
x = \begin{bmatrix} 0 & 0 & 1 & 4 & 8 \\ 0 & 1 & 4 & 8 & 4 \\ 1 & 4 & 8 & 4 & 1 \\ 4 & 8 & 4 & 1 & 0 \\ 8 & 4 & 1 & 0 & 0 \end{bmatrix}.
$$

**Regular grid.** The nine taps read rows 1 to 3 and columns 1 to 3. The values sum to
$1 + 4 + 8 + 4 + 8 + 4 + 8 + 4 + 1 = 42$, so $y = 42/9 = 4.67$. Three taps lie on the ridge; the corner taps $(1, 1)$
and $(3, 3)$ read the dark background value 1.

**Offsets.** Suppose the offset branch predicts the offsets in the table. The three taps on the ridge keep zero offsets.
The four edge taps move half a pixel towards the ridge. The two off-ridge corners move most.

| Tap $\pvec_n$ | Regular position | Offset $\Delta\pvec_n$ | Sampled position | Sample |
| --- | --- | --- | --- | --- |
| $(-1, -1)$ | $(1, 1)$ | $(0.4, 0.8)$ | $(1.4, 1.8)$ | $4.92$ |
| $(-1, 0)$ | $(1, 2)$ | $(0, 0.5)$ | $(1, 2.5)$ | $6$ |
| $(-1, 1)$ | $(1, 3)$ | $(0, 0)$ | $(1, 3)$ | $8$ |
| $(0, -1)$ | $(2, 1)$ | $(0.5, 0)$ | $(2.5, 1)$ | $6$ |
| $(0, 0)$ | $(2, 2)$ | $(0, 0)$ | $(2, 2)$ | $8$ |
| $(0, 1)$ | $(2, 3)$ | $(-0.5, 0)$ | $(1.5, 3)$ | $6$ |
| $(1, -1)$ | $(3, 1)$ | $(0, 0)$ | $(3, 1)$ | $8$ |
| $(1, 0)$ | $(3, 2)$ | $(0, -0.5)$ | $(3, 1.5)$ | $6$ |
| $(1, 1)$ | $(3, 3)$ | $(-0.8, -0.4)$ | $(2.2, 2.6)$ | $4.92$ |

**One sample in full.** The first tap reads $(1.4, 1.8)$, so $r = 1$, $c = 1$, $\alpha = 0.4$ and $\beta = 0.8$. The
four neighbours are $x_{00} = x(1, 1) = 1$, $x_{01} = x(1, 2) = 4$, $x_{10} = x(2, 1) = 4$ and $x_{11} = x(2, 2) = 8$.
The weights are

$$
(1 - 0.4)(1 - 0.8) = 0.12, \quad (1 - 0.4)(0.8) = 0.48, \quad (0.4)(1 - 0.8) = 0.08, \quad (0.4)(0.8) = 0.32,
$$

which sum to 1. The sample is
$0.12 \cdot 1 + 0.48 \cdot 4 + 0.08 \cdot 4 + 0.32 \cdot 8 = 0.12 + 1.92 + 0.32 + 2.56 = 4.92$.

**Half-pixel samples.** The edge tap at $(1, 2.5)$ has $\alpha = 0$ and $\beta = 0.5$, so it averages $x(1, 2) = 4$ and
$x(1, 3) = 8$ to give 6. The other three edge taps also average a 4 and an 8.

**Output.** The samples sum to $2 \cdot 4.92 + 4 \cdot 6 + 3 \cdot 8 = 57.84$, so $y = 57.84 / 9 = 6.43$. The same nine
weights give 4.67 on the regular grid and 6.43 on the deformed one: the kernel now reads the ridge.

**Gradient.** For the first tap, $\partial x / \partial \alpha = (1 - 0.8)(4 - 1) + 0.8\,(8 - 4) = 0.6 + 3.2 = 3.8$ and
$\partial x / \partial \beta = (1 - 0.4)(4 - 1) + 0.4\,(8 - 4) = 1.8 + 1.6 = 3.4$. Multiplying by $w_1 = 1/9$ gives
$\partial y / \partial \Delta\pvec_1 = (0.42,\ 0.38)$. If the loss rewards a larger output,
<NoteLink to="gradient-descent">gradient descent</NoteLink> moves the tap further down and to the right, towards the
bright pixel $(2, 2)$.

## Assumptions

- **Geometry varies within the data.** The offsets pay off when object scale, pose or shape changes across images and
  across positions, as in detection and segmentation of natural scenes. Aligned, fixed-scale inputs gain little.
- **The feature map is smooth between pixels.** Bilinear interpolation treats the map as a piecewise-bilinear surface.
  Deep feature maps are smooth enough; a map of isolated spikes gives samples and gradients that change abruptly between
  cells.
- **One offset per tap and group.** In DCNv1 and DCNv2 all input channels share the offsets of a tap. Features in
  different channels that need different sampling positions must compromise, which is what the groups of DCNv3 relax.

## Pitfalls

- **Local gradients.** The offset gradient sees only the $2 \times 2$ cell around each sample. In a flat region of the
  feature map it is zero and the offset stops moving; a target more than a pixel away is found only through a chain of
  local improvements.
- **Unstable offsets.** Large learning rates let offsets jump across cells, and training can diverge. Zero
  initialisation of the offset branch and a reduced learning rate for it are the standard remedies
  <Cite id="zhu2019deformable" />.
- **Samples outside the image.** Unbounded offsets can push taps past the border, where they read zeros. Units near the
  border then lose part of their input.
- **<Gloss name="flop" plural /> understate the cost.** The gathers at data-dependent addresses run far slower than the
  multiply-adds suggest, and a model that is cheap in FLOPs can be slow in wall-clock time. Measure latency on the
  target hardware.
- **Deployment.** The operator is not part of every inference runtime or compiler, and a model that uses it may need a
  custom kernel to export.
