<Definition>
Tool use lets a <Gloss name="language-model">language model</Gloss> call external functions, such as a calculator, a
search engine or a code interpreter, while it generates. The model emits a call in a fixed format, a runtime executes
it, and the result is inserted into the model's context. An **agent** is a model run in a loop of this kind: it chooses
an action, observes the result and decides the next action, until it produces a final answer or a step limit is reached
<Cite id="yao2023" />.
</Definition>

## Problem

A language model's knowledge is fixed at training time and stored imprecisely in its weights. It cannot read a
document it was not given, check today's price, or run code. It is also unreliable at exact computation such as
multi-digit arithmetic, which simple programs do perfectly <Cite id="schick2023" />. Tools supply these abilities. The
model has to decide when to call a tool, with what arguments, and how to use the result.

## Mechanism

### Function calling

1. **Declare tools.** Each tool is described in the prompt by a name, a natural-language description, and a schema for
   its arguments, usually JSON Schema.
2. **Emit a call.** The model generates a call in a reserved format, for example
   `{"name": "get_weather", "arguments": {"city": "Cork"}}`, delimited by special tokens that the runtime detects.
   Generation stops at the call.
3. **Execute.** The runtime parses the call, validates the arguments against the schema and runs the function.
4. **Observe.** The result is appended to the context as a tool message, and generation resumes.

Models are fine-tuned on conversations that contain such calls, so that they produce well-formed calls and use results
correctly. The model never executes anything itself: it only writes text that the runtime chooses to act on.

### The agent loop

```text
context ← task description, tool declarations, user request
for step = 1 … max_steps:
    output ← model(context)
    if output is a final answer: return it
    result ← execute(output.tool_call)
    context ← context + output + result
return failure
```

**ReAct** prompts the loop with interleaved text of three kinds: *Thought* (free-text reasoning about what to do next),
*Action* (a tool call) and *Observation* (the tool's result) <Cite id="yao2023" />. The thoughts play the role of a
<NoteLink to="chain-of-thought">chain of thought</NoteLink>, but they are grounded by observations between steps. On the
HotpotQA and FEVER <Gloss name="qa">question-answering</Gloss> and fact-verification tasks, with a simple Wikipedia
search API, ReAct reduced the hallucination and error propagation seen in chain-of-thought reasoning alone. On the
interactive ALFWorld and WebShop tasks, prompted with one or two examples, it exceeded imitation and
<Gloss name="rl">reinforcement learning</Gloss> baselines by 34 and 10 percentage points of absolute success rate
<Cite id="yao2023" />.

### Learning where calls help: Toolformer

Toolformer teaches a model to use tools from unlabelled text <Cite id="schick2023" />. Starting from a few
demonstrations per tool, the model proposes candidate calls $c_i$ at positions $i$ in ordinary text and executes them to
get results $r_i$. A call is kept only if it makes the following text easier to predict. Define the weighted loss on the
tokens after position $i$ given a prefix $z$ inserted before them,

$$
L_i(z) = -\sum_{j \ge i} w_{j-i} \log p(x_j \mid z, x_{1:j-1}),
$$

with weights $w$ that decrease with distance. Compare three prefixes: the call with its result, $e(c_i, r_i)$; the call
without its result, $e(c_i, \varepsilon)$; and no call, $\varepsilon$. Let

$$
L_i^+ = L_i\big(e(c_i, r_i)\big), \qquad L_i^- = \min\Big(L_i(\varepsilon),\; L_i\big(e(c_i, \varepsilon)\big)\Big).
$$

The call is kept when $L_i^- - L_i^+ \ge \tau_f$ for a threshold $\tau_f > 0$. Because of the minimum in $L_i^-$, a call
must beat both making no call and making the call but ignoring its result, so it is kept only when the *result* carries
information about the upcoming text. The model is then fine-tuned on text with the kept calls inserted, and learns to
emit calls where they reduced loss. Toolformer used a calculator, a question-answering system, two search engines, a
translation system and a calendar <Cite id="schick2023" />.

## Cost

- **Context growth.** Each step appends the model's output and the tool's result. With $n$ steps adding $s$ tokens
  each to a prompt of $c_0$ tokens, the final context has $c_0 + ns$ tokens, and the total number of tokens read
  across all steps without caching is $n c_0 + s\,n(n+1)/2$, quadratic in $n$. Caching the keys and values of the
  unchanged prefix removes the recomputation but not the growing attention cost.
- **Latency.** Every step waits for a model call and a tool call in series.

### Worked example

An agent solves a task in 20 steps, and each step is correct independently with probability $q$. The task succeeds only
if every step is correct, with probability $q^{20}$.

- $q = 0.95$ gives $0.95^{20} = 0.358$.
- $q = 0.99$ gives $0.99^{20} = 0.818$.

A per-step error rate that looks small compounds over a long task. Agents that verify results and retry failed steps
raise the effective $q$.

## Trade-offs

- **Tool outputs are untrusted input.** A web page or document returned by a tool enters the context with the same
  standing as the user's request. Instructions embedded in it can redirect the agent (prompt injection). Actions with
  side effects, such as sending messages or spending money, need confirmation or restricted permissions.
- **Termination.** An agent can loop, repeating a failing action. A step limit bounds cost, and failures must be
  reported rather than hidden.
- **Grounding reduces but does not remove hallucination.** The model can misread a result, or answer from memory
  instead of calling a tool; see <NoteLink to="hallucination-and-faithfulness">hallucination and
  faithfulness</NoteLink>.
- **Retrieval is a special case.** Calling a search tool and conditioning on what it returns is
  <NoteLink to="retrieval-augmented-generation">retrieval-augmented generation</NoteLink> performed step by step.
