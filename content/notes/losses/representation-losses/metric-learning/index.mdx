<Definition>
**Metric learning** chooses a distance function $d(\xvec, \xvec')$ from labelled data, so that points with the same
label are close and points with different labels are far apart. A **Mahalanobis metric** has the form
$d_{\Mmat}(\xvec, \xvec') = \sqrt{(\xvec - \xvec')^\top \Mmat (\xvec - \xvec')}$ with a symmetric
<NoteLink to="positive-definite-matrices">positive semidefinite</NoteLink> $d \times d$ matrix $\Mmat$, which is the
parameter learned. **Deep metric learning** instead learns a network $f_{\thetavec}: \reals^d \to \reals^k$ and uses
$d(\xvec, \xvec') = \norm{f_{\thetavec}(\xvec) - f_{\thetavec}(\xvec')}$. The learned distance is then used by
distance-based methods such as <NoteLink to="k-nearest-neighbours">$k$-nearest neighbours</NoteLink>, clustering and
retrieval.
</Definition>

## Why learn the distance

Nearest-neighbour methods, clustering and retrieval all depend on which points count as close.
<NoteLink to="pairwise-distances-and-cosine-similarity">Euclidean distance</NoteLink> weights every feature equally and
ignores correlations. A feature with large variance and no relation to the label dominates the distance and hides the
features that matter. Rescaling by hand works for a few features; metric learning does it from the labels. The same
labels can come as classes, or only as pairs marked similar and dissimilar <Cite id="xing2002" />.

## A Mahalanobis metric is Euclidean distance after a linear map

Every positive semidefinite $\Mmat$ factorises as $\Mmat = \Lmat^\top \Lmat$ for some matrix $\Lmat$. One choice uses
the <NoteLink to="eigendecomposition">eigendecomposition</NoteLink> $\Mmat = \Qmat \Lambdamat \Qmat^\top$, whose
eigenvalues $\lambda_i \ge 0$ because $\Mmat$ is positive semidefinite, and sets $\Lmat = \Lambdamat^{1/2} \Qmat^\top$.
Then

$$
d_{\Mmat}(\xvec, \xvec')^2 = (\xvec - \xvec')^\top \Lmat^\top \Lmat (\xvec - \xvec') = \norm{\Lmat\xvec - \Lmat\xvec'}^2 .
$$

Learning $\Mmat$ is therefore the same as learning a <NoteLink to="matrix-vector-product">linear map</NoteLink> $\Lmat$
and measuring ordinary Euclidean distance in the mapped space. Three consequences follow.

- **The triangle inequality holds**, because it holds for the <NoteLink to="vector-norms">Euclidean norm</NoteLink> of
  $\Lmat\xvec - \Lmat\xvec'$.
- **A singular $\Mmat$ gives a pseudometric.** If $\Mmat$ has a zero eigenvalue with eigenvector $\vvec$, then
  $d_{\Mmat}(\xvec, \xvec + t\vvec) = 0$ for all $t$. The metric ignores the direction $\vvec$ entirely.
- **A low-rank $\Lmat$ reduces dimension.** With $\Lmat \in \reals^{k \times d}$ and $k < d$, the map projects the data
  to $k$ dimensions.

The classical <NoteLink to="mahalanobis-distance-outliers">Mahalanobis distance</NoteLink> is the special case
$\Mmat = \Sigmamat^{-1}$, the inverse covariance of the data. It is fixed by the data, not learned from labels.

## Pairwise constraints: the first convex formulation

Xing et al. took a set $\Scal$ of similar pairs and a set $\Dcal$ of dissimilar pairs and solved
<Cite id="xing2002" />

$$
\min_{\Mmat \succeq 0} \sum_{(i, j) \in \Scal} d_{\Mmat}(\xvec_i, \xvec_j)^2
\quad \text{subject to} \quad \sum_{(i, j) \in \Dcal} d_{\Mmat}(\xvec_i, \xvec_j) \ge 1 .
$$

The objective is linear in $\Mmat$. The constraint function is a sum of square roots of linear functions of $\Mmat$, so
it is concave, and the set where a concave function is at least 1 is convex. The positive semidefinite matrices form a
convex cone. The problem is therefore convex and has no spurious local optima.

The constraint uses distances, not squared distances. With squared distances in the constraint the optimum always has
rank one, so the data are projected onto a line <Cite id="xing2002" />. Write
$\Amat_\Scal = \sum_{\Scal} (\xvec_i - \xvec_j)(\xvec_i - \xvec_j)^\top$ and $\Amat_\Dcal$ likewise. Then
$\sum_\Scal d_{\Mmat}^2 = \trace(\Mmat\Amat_\Scal)$ and $\sum_\Dcal d_{\Mmat}^2 = \trace(\Mmat\Amat_\Dcal)$. Because
$\Mmat$ can be rescaled freely, the problem minimises the ratio $\trace(\Mmat\Amat_\Scal) / \trace(\Mmat\Amat_\Dcal)$.
Write $\Mmat = \sum_k \lambda_k \vvec_k \vvec_k^\top$ with $\lambda_k \ge 0$. The ratio becomes

$$
\frac{\sum_k \lambda_k\, \vvec_k^\top \Amat_\Scal \vvec_k}{\sum_k \lambda_k\, \vvec_k^\top \Amat_\Dcal \vvec_k}
\;\ge\; \min_k \frac{\vvec_k^\top \Amat_\Scal \vvec_k}{\vvec_k^\top \Amat_\Dcal \vvec_k},
$$

since a ratio of sums of non-negative terms is at least the smallest term-by-term ratio. The bound is attained by
putting all the weight on the best single direction, so a rank-one $\Mmat = \vvec\vvec^\top$ is optimal. The best
$\vvec$ minimises the generalised <NoteLink to="spectral-theorem">Rayleigh quotient</NoteLink>
$\vvec^\top \Amat_\Scal \vvec / \vvec^\top \Amat_\Dcal \vvec$, the same kind of problem as
<NoteLink to="linear-discriminant-analysis">Fisher's discriminant</NoteLink>. The square root in Xing's constraint
breaks this linearity.

## Neighbourhood components analysis

Goldberger et al. optimised $\Lmat$ for nearest-neighbour classification directly <Cite id="goldberger2004" />. Each
point $i$ picks a neighbour $j \ne i$ at random with probability

$$
p_{ij} = \frac{\exp\paren{-\norm{\Lmat\xvec_i - \Lmat\xvec_j}^2}}{\sum_{k \ne i} \exp\paren{-\norm{\Lmat\xvec_i - \Lmat\xvec_k}^2}},
$$

and is classified correctly if the neighbour shares its label. **NCA** maximises the expected number of correct
classifications, $\sum_i \sum_{j:\, y_j = y_i} p_{ij}$. This is a smooth version of the leave-one-out accuracy of
1-nearest neighbour. It is differentiable in $\Lmat$ but not convex, and a rectangular $\Lmat$ learns a low-dimensional
embedding at the same time. The softmax over neighbours is the same construction that later appears in proxy-based and
contrastive losses.

## Large margin nearest neighbour

**LMNN** fixes, for each point $\xvec_i$, a few **target neighbours** $j \rightsquigarrow i$: its nearest neighbours of
the same class under Euclidean distance <Cite id="weinberger2009b" />. An **impostor** of $\xvec_i$ is a point $\xvec_l$
of another class with $\norm{\Lmat(\xvec_i - \xvec_l)}^2 \le \norm{\Lmat(\xvec_i - \xvec_j)}^2 + 1$ for some target
neighbour $j$: it invades the neighbourhood, or comes within the unit margin of it. The loss is

$$
\varepsilon(\Lmat) = (1 - \mu)\sum_{i,\, j \rightsquigarrow i} \norm{\Lmat(\xvec_i - \xvec_j)}^2
+ \mu \sum_{i,\, j \rightsquigarrow i} \sum_l (1 - y_{il}) \brack{1 + \norm{\Lmat(\xvec_i - \xvec_j)}^2 - \norm{\Lmat(\xvec_i - \xvec_l)}^2}_+ ,
$$

where $y_{il} = 1$ if $\xvec_i$ and $\xvec_l$ share a label and $0$ otherwise, and $\mu \in [0, 1]$ weights the two
terms ($\mu = 0.5$ worked well in practice) <Cite id="weinberger2009b" />. The first term pulls target neighbours in.
The second is a triplet <Gloss name="hinge-loss">hinge loss</Gloss> with unit margin on squared distances: it pushes
impostors out. Pulling only target neighbours, not every same-class point, lets a class spread over several clusters,
which is all $k$-nearest neighbours needs. Written in $\Mmat = \Lmat^\top\Lmat$, every squared distance is linear in
$\Mmat$, the hinge of a linear function is convex, and the problem is a semidefinite program with a global optimum.

## Deep metric learning

A linear map cannot separate classes that are not linearly arranged, such as faces of the same person in different
poses. Deep metric learning replaces $\Lmat\xvec$ by a network $f_{\thetavec}(\xvec)$ and trains it with a loss on
distances between embeddings:

- the <NoteLink to="triplet-and-margin-losses">pair and triplet margin losses</NoteLink>, which compare pairs or
  triplets of examples <Cite id="hadsell2006" /> <Cite id="schroff2015" />;
- <NoteLink to="proxy-and-classification-based-metric-losses">proxy and classification-based losses</NoteLink>, which
  compare each example with one learned vector per class;
- the InfoNCE loss of <NoteLink to="contrastive-learning">contrastive learning</NoteLink>, a softmax over one positive
  and many negatives, which needs no labels when positives are augmented views of the same input.

None of these losses is convex in $\thetavec$.

At test time the classes are often new: a face-verification system compares people it never saw in training. The
embedding is evaluated by retrieval metrics such as Recall@$K$ and <Gloss name="mean-average-precision">mean average
precision</Gloss> at $R$ (MAP@R), computed on classes held out from training <Cite id="musgrave2020" />. Retrieval over
millions of embeddings uses <NoteLink to="nearest-neighbour-search">approximate nearest-neighbour search</NoteLink>.

## Worked example

Four points in $\reals^2$: class A has $\xvec_1 = (0, 0)$ and $\xvec_2 = (0, 3)$; class B has $\xvec_3 = (1, 0)$ and
$\xvec_4 = (1, 3)$. The label depends only on the first coordinate.

**Euclidean distance.** The nearest neighbour of $\xvec_1$ is $\xvec_3$ at distance 1, not $\xvec_2$ at distance 3. The
same happens for every point, so leave-one-out 1-nearest-neighbour accuracy is $0$ out of $4$.

**A diagonal metric.** With $\Lmat = \diag(1, 0.1)$, so $\Mmat = \diag(1, 0.01)$, $d_{\Mmat}(\xvec_1, \xvec_2) = 0.3$
and $d_{\Mmat}(\xvec_1, \xvec_3) = 1$. Every point's nearest neighbour now shares its label: accuracy $4$ out of $4$.
The NCA objective, the expected number of correct stochastic neighbours, rises from $0.001$ under $\Lmat = \eye$ to
$2.26$ under $\Lmat = \diag(1, 0.1)$.

**Xing's problem with squared distances.** The similar pairs are $(1, 2)$ and $(3, 4)$, the dissimilar pairs the other
four. Then $\Amat_\Scal = \diag(0, 18)$ and $\Amat_\Dcal = \diag(4, 18)$. The generalised Rayleigh quotient is $0$ along
$\vvec = (1, 0)$, so the optimum is the rank-one $\Mmat = \frac{1}{4}\,\vvec\vvec^\top$. It meets the constraint
$\trace(\Mmat\Amat_\Dcal) = 1$ with objective $0$. The learned distance is $\abs{x_1 - x'_1}/2$: it discards the second
coordinate completely. Here that is correct, but on data where both coordinates carry signal, a rank-one metric throws
one of them away.

## Assumptions

- **Supervision defines similarity.** Labels or similar/dissimilar pairs must reflect the notion of closeness the task
  needs. The metric learns nothing else.
- **A linear map is enough** for Mahalanobis methods. When classes are not linearly arranged, a kernel or a deep
  embedding is needed.
- **Target neighbours are fixed** in LMNN. They are chosen by Euclidean distance before training, so a poor initial
  metric gives poor targets.

## Pitfalls

- **Rank collapse.** Formulations whose objective and constraint are both linear in $\Mmat$ can return a rank-one
  metric, as the derivation above shows.
- **Scale.** Constraints such as "dissimilar pairs at least 1 apart" fix the scale of $\Mmat$. Without them, shrinking
  $\Mmat$ toward zero trivially brings similar pairs together.
- **Cost of the semidefinite constraint.** Projecting $\Mmat$ onto the positive semidefinite cone needs an
  eigendecomposition per step, $O(d^3)$ for $d$ features. Optimising $\Lmat$ directly avoids the constraint but loses
  convexity.
- **Evaluation leakage.** Deep metric-learning papers have tuned hyperparameters on test classes and compared methods
  with different networks and embedding sizes. Under a common protocol, most gains since 2006 were small
  <Cite id="musgrave2020" />.
