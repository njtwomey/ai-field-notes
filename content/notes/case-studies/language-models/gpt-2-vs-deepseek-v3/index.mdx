## Architecture

**GPT-2.** GPT-2 is a stack of 48 identical <NoteLink to="transformer">transformer</NoteLink> decoder blocks with causal
self-attention. It follows the original <Gloss name="gpt" /> design <Cite id="radford2018" /> with three changes
<Cite id="radford2019" />. <NoteLink to="layer-normalisation">Layer normalisation</NoteLink> is moved to the input of each
sub-block (pre-norm), and an extra layer normalisation follows the final block. The weights of residual layers are scaled
at initialisation by $1/\sqrt{N}$, where $N$ is the number of residual layers. The vocabulary grows to 50,257 tokens and
the context to 1,024 tokens. Every block has standard
<NoteLink to="multi-head-attention">multi-head attention</NoteLink> and a dense feed-forward layer, so every parameter is
used for every token. Positions enter as learned absolute
<NoteLink to="positional-encoding">position embeddings</NoteLink> added to the token embeddings.

**DeepSeek-V3.** DeepSeek-V3 has 61 transformer blocks of width 7,168 <Cite id="deepseek2024" />. Two components differ
from GPT-2.

- **<Gloss name="mla">Multi-head latent attention (MLA)</Gloss>.** Each token's hidden state is projected down to a 512-dimension latent vector
  $\cvec_t$. The keys and values of all 128 heads are reconstructed from $\cvec_t$ by up-projections. A separate
  64-dimension key carries the <Gloss name="rope">rotary position embedding</Gloss> <Cite id="su2021" />, shared across heads. Queries are
  compressed too, to 1,536 dimensions, which saves activation memory in training.
- **Mixture of experts (MoE).** In 58 of the 61 blocks, the feed-forward layer is a
  <NoteLink to="mixture-of-experts">mixture of experts</NoteLink> <Cite id="shazeer2017" />: one shared expert that every
  token uses, and 256 routed experts of which a router picks 8 per token. Each token is sent to experts on at most 4
  nodes, which bounds communication. The router balances load mainly without an auxiliary loss, keeping only a very small sequence-wise balance loss. It adds a per-expert bias to
  the routing scores, raising it for under-used experts and lowering it for over-used ones. The bias affects only which
  experts are chosen, not how their outputs are weighted <Cite id="deepseek2024" />.

**Where the parameters are.** If each expert has three $7{,}168 \times 2{,}048$ weight matrices, as a gated (<Gloss name="swiglu" />)
feed-forward block does, one expert holds $3 \times 7{,}168 \times 2{,}048 = 44.0$M parameters. The 257 experts in each
of 58 layers then hold 656B parameters, 98% of the 671B total. A token passes through 9 experts per layer, about 23B
parameters, plus attention and the dense layers. That is how the model reaches 37B activated parameters while storing
18 times as many.

## Training

**GPT-2** was trained on WebText, a corpus built from outbound Reddit links with at least 3 karma: about 8 million
documents and 40 GB of text after de-duplication, with Wikipedia removed <Cite id="radford2019" />. The <NoteLink to="minibatching-and-batch-size">batch size</NoteLink> was
512 sequences of 1,024 tokens. The paper reports neither the number of training tokens nor the compute. All four model
sizes still underfit WebText at the end of training <Cite id="radford2019" />.

**DeepSeek-V3** was pre-trained on 14.8T tokens with a 4K context, then extended to 32K and then 128K tokens with <Gloss name="yarn" />
<Cite id="deepseek2024" />. Besides <NoteLink to="autoregressive-transformer-language-model">next-token prediction</NoteLink>, it predicts one additional future token through a small
sequential module (multi-token prediction with depth 1). Pre-training used an FP8
<NoteLink to="mixed-precision-training">mixed-precision</NoteLink> framework: <NoteLink to="matrix-multiplication">matrix multiplications</NoteLink> run in 8-bit floating
point, with activations quantised in tiles of $1 \times 128$ and weights in blocks of $128 \times 128$, each with its own
scale factor. Pre-training took 2,664K H800 <Gloss name="gpu" /> hours and the full run, including context extension and post-training,
2.788M <Cite id="deepseek2024" />. As a rough check, the standard estimate of $6ND$ training <Gloss name="flop" plural />, for $N = 37$B active
parameters and $D = 14.8$T tokens, gives $3.3 \times 10^{24}$ FLOPs.

## What is distinctive

**GPT-2** showed that a <Gloss name="language-model">language model</Gloss> trained only to predict the next token on a large, diverse web corpus performs
many tasks zero-shot. The largest model set state-of-the-art zero-shot results on 7 of 8 language-modelling datasets,
for example a perplexity of 17.48 on WikiText-103 without fine-tuning <Cite id="radford2019" />. Architecturally it is a
plain dense transformer.

**DeepSeek-V3** combines three efficiency measures at a scale where they matter. MLA shrinks the
<NoteLink to="key-value-cache">KV cache</NoteLink>. The MoE layers decouple stored parameters from per-token compute. FP8
training cuts memory and time per step. The base model scores 87.1 on <Gloss name="mmlu" /> <Cite id="deepseek2024" />.

## Comparison

**Scale.** DeepSeek-V3 stores 435 times as many parameters as GPT-2 and activates 24 times as many per token. Its width
is 4.5 times GPT-2's, its depth 1.3 times.

**KV cache per token.** At inference, a decoder caches keys and values for every past token in every layer. GPT-2 caches
$2 \times 48 \times 1{,}600 = 153{,}600$ numbers per token. Standard multi-head attention with DeepSeek-V3's shape would
cache $2 \times 61 \times 128 \times 128 = 1{,}998{,}848$. MLA caches the 512-dimension latent plus the 64-dimension
rotary key, $61 \times (512 + 64) = 35{,}136$ numbers per token: 57 times less than the equivalent multi-head attention,
and 4.4 times less than GPT-2, a model 435 times smaller. The up-projections that rebuild keys and values can be folded
into the query and output projections at inference, so the full keys and values are never materialised.

**Compute per token.** A forward pass costs about $2N$ FLOPs for $N$ active parameters: about 3 GFLOPs per token for
GPT-2 and 74 GFLOPs for DeepSeek-V3. A dense model with DeepSeek-V3's 671B parameters would cost 18 times as much per
token.

**Positions and context.** GPT-2's learned absolute embeddings exist only for the 1,024 positions seen in training.
Rotary embeddings encode relative position in the query-key product, which allowed DeepSeek-V3's context to be extended
from 4K to 128K after pre-training.

**Tokenisers.** Both use <NoteLink to="byte-pair-encoding">byte-level BPE</NoteLink>, so both can encode any string.
DeepSeek-V3's vocabulary is 2.5 times larger, which shortens sequences, especially for code and languages other than
English.
