<Definition>
**Reinforcement learning** (RL) is the problem of learning to act from reward. An agent interacts with an environment
modelled as a <NoteLink to="markov-decision-process">Markov decision process</NoteLink>: at each step it observes a
state, takes an action, and receives a reward and a next state. Its goal is a policy that maximises the expected
discounted return. Unlike planning, RL does not assume the transition probabilities and rewards are known; it learns
from the transitions it experiences <Cite id="sutton2018" />.
</Definition>

## Components

Component notes fall into four groups.

- **Markov decision processes.** The model and its exact solution when the model is known: the
  <NoteLink to="markov-decision-process">MDP</NoteLink>, the <NoteLink to="bellman-equations">Bellman
  equations</NoteLink>, <NoteLink to="value-iteration">value iteration</NoteLink> and
  <NoteLink to="policy-iteration">policy iteration</NoteLink>.
- **Value-based methods.** Learn $q_*$ or $v_\pi$ from samples and act greedily:
  <NoteLink to="temporal-difference-learning">temporal-difference learning</NoteLink>,
  <NoteLink to="sarsa">SARSA</NoteLink>, <NoteLink to="q-learning">Q-learning</NoteLink> and
  <NoteLink to="deep-q-network">deep Q-networks</NoteLink>, with
  <NoteLink to="exploration-in-reinforcement-learning">exploration</NoteLink> to gather informative data.
- **Policy methods.** Adjust a parameterised policy along an estimate of the return's <NoteLink to="gradient">gradient</NoteLink>: the
  <NoteLink to="policy-gradient-theorem">policy gradient theorem</NoteLink>,
  <NoteLink to="actor-critic">actor-critic</NoteLink> methods,
  <NoteLink to="trust-region-and-proximal-policy-optimisation">trust-region and proximal policy optimisation (TRPO and PPO)</NoteLink>,
  <NoteLink to="deterministic-policy-gradients">deterministic policy gradients</NoteLink>, and
  <NoteLink to="reinforcement-learning-from-human-feedback">reinforcement learning from human feedback (RLHF)</NoteLink> for fine-tuning <Gloss name="language-model">language models</Gloss> from preferences.
- **Model-based and offline RL.** Learn or use a model to plan (<NoteLink to="model-based-reinforcement-learning">model-based
  RL</NoteLink>), learn from a fixed dataset (<NoteLink to="offline-reinforcement-learning">offline RL</NoteLink>), and estimate a policy's
  value from another policy's data (<NoteLink to="off-policy-evaluation-in-reinforcement-learning">off-policy evaluation</NoteLink>).

## Data flow

Every method alternates two activities. **Evaluation** estimates the value of the current policy, as a <Gloss name="value-function">value
function</Gloss> or a return. **Improvement** changes the policy towards actions that the evaluation rates higher. Dynamic
programming does both exactly from a model. Learning methods replace exact <NoteLink to="expectation">expectations</NoteLink> by samples, which introduces
three problems absent from supervised learning:

<AgentLoopDiagram />

- **Credit assignment.** A reward may be caused by an action taken many steps earlier. Bootstrapping from value
  estimates, and discounting, spread credit backwards.
- **Exploration.** The agent's data depends on its own actions. An agent that never tries an action never learns its
  value. The <NoteLink to="multi-armed-bandit">multi-armed bandit</NoteLink> is the one-state version of this problem.
- **Non-stationary targets.** Value targets are built from the agent's own estimates, which change as it learns.

## Variants

- **On-policy and off-policy.** On-policy methods learn about the policy generating the data; off-policy methods learn
  about a different one, such as the greedy policy, from the same data.
- **Model-free and model-based.** Model-free methods learn values or policies directly; model-based methods learn
  the transition probabilities $p$ and rewards $r$ and plan with them.
- **Online and offline.** Online methods collect their own data; offline methods must learn from a fixed log.
- **Tabular and approximate.** Tables store one value per state; large or continuous problems need function
  approximation, usually a neural network, which removes most convergence guarantees.

## Applications

- **Recommendation.** A recommender's choices change what users want and do next, so optimising long-term value, such
  as retention, instead of the next click is a sequential decision problem. The obstacles are typical of applied RL:
  enormous action spaces, sparse and delayed rewards, and exploration too risky to run on live users, which forces
  offline training and <Gloss name="ope">off-policy evaluation</Gloss>. See <NoteLink to="reinforcement-learning-for-recommendation">reinforcement
  learning for recommendation</NoteLink>.
