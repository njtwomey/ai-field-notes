<Definition>
**Model-based reinforcement learning** uses a model of the environment, a transition distribution
$\hat p(s' \mid s, a)$ and a reward function $\hat r(s, a)$, to improve a policy by computation rather than by more
interaction. The model is either known, as the rules of a board game are, or learned from observed transitions by
supervised learning. Planning with it means computing values or actions from simulated transitions, by dynamic
programming, by sampled updates, or by search from the current state <Cite id="sutton2018" />.
</Definition>

## Intuition

Model-free methods such as <NoteLink to="q-learning">Q-learning</NoteLink> use each real transition once or a few times
and forget it. A model stores what was learned about the dynamics, and planning extracts its consequences for every
state and action without spending more real interactions. When interaction is expensive, as with robots, patients or
slow simulators, this matters. The cost is that the policy is only as good as the model: a planner will exploit any
error in the model that makes a bad action look good.

## Dyna: learning, planning and acting together

**Dyna-Q** interleaves three processes after every real step $(S, A, R, S')$ <Cite id="sutton1990" />:

1. **Direct RL:** a Q-learning update on the real transition.
2. **Model learning:** record $\hat p$ and $\hat r$ for $(S, A)$; in a deterministic tabular world, store $(R, S')$.
3. **Planning:** repeat $n$ times: pick a previously seen pair $(s, a)$ at random, simulate $(r, s')$ from the model,
   and apply the same Q-learning update to the simulated transition.

Real and simulated experience are processed identically. With $n = 0$ Dyna-Q is Q-learning; with larger $n$ each real
step is followed by $n$ imagined ones, and values propagate backwards through the known transitions far faster than
real experience alone could carry them. On a maze where reward appears only at the goal, Q-learning propagates the goal
value back one state per episode, whereas Dyna-Q with 50 planning steps finds the path within a few episodes
<Cite id="sutton2018" />.

## Compounding model error

A learned model that is accurate for one step can be poor for many. Let the one-step model have error at most
$\varepsilon$ in total variation, $\operatorname{TV}(\hat p(\cdot \mid s, a), p(\cdot \mid s, a)) \le \varepsilon$ for
all $s, a$, where $\operatorname{TV}(P, Q) = \sup_E\abs{P(E) - Q(E)}$. Let $d_k$ be the total-variation distance between
the true and modelled state distributions $k$ steps into a rollout of a fixed policy from the same start. One step
from two distributions $\rho$ and $\hat\rho$ gives

$$
d_{k+1} \le \underbrace{\operatorname{TV}\paren{\rho P,\ \hat\rho P}}_{\le\,d_k} + \underbrace{\operatorname{TV}\paren{\hat\rho P,\ \hat\rho\hat P}}_{\le\,\varepsilon},
$$

by the triangle inequality: the first term because a Markov kernel cannot increase total variation, the second because
each state's next-state distribution is within $\varepsilon$. Starting from $d_0 = 0$, $d_k \le k\varepsilon$. For a
reward bounded by $R_{\max}$, $\abs{\expect_P[r] - \expect_Q[r]} \le 2R_{\max}\operatorname{TV}(P, Q)$, so the error in
the discounted return is at most

$$
\sum_{k \ge 1}\gamma^k\,2R_{\max}\,k\varepsilon = \frac{2\gamma\,\varepsilon R_{\max}}{(1 - \gamma)^2}.
$$

The error grows with the square of the effective horizon $1/(1 - \gamma)$, while the return itself grows only
linearly. Long imagined rollouts are therefore unreliable, and practical methods use short model rollouts branched from
real states, or plan only a few steps ahead and bootstrap from a learned value function.

## Monte Carlo tree search

**Monte Carlo tree search** (MCTS) plans from the current state only. It grows a search tree by repeated simulations,
each with four phases:

1. **Selection.** From the root, descend through the tree choosing actions by a bandit rule.
2. **Expansion.** Add a new leaf node for the first state reached that is not in the tree.
3. **Evaluation.** Estimate the leaf's value, originally by a random rollout to the end of the game.
4. **Backup.** Add the result to the visit counts $N$ and mean values $Q$ of every node on the path.

**UCT** uses <NoteLink to="ucb1">UCB1</NoteLink> for selection, treating each node's actions as a bandit:
$\argmax_a[Q(s, a) + c\sqrt{\ln N(s)/N(s, a)}]$. The exploration term shrinks as an action is tried, so the search
concentrates on promising lines while still checking others, and the value estimate at the root converges to the
minimax or optimal value as the number of simulations grows <Cite id="kocsis2006" />.

## AlphaZero and MuZero

**AlphaGo** combined MCTS with deep networks trained first on human games and then by self-play, and defeated a
professional Go player <Cite id="silver2016" />. **AlphaGo Zero** and **AlphaZero** learned from self-play alone, with
one network $f_{\thetavec}(s) = (\pvec, v)$ that outputs a policy prior $\pvec$ over moves and a value estimate $v$
<Cite id="silver2017" /> <Cite id="silver2018" />:

- **Search.** MCTS selects by the PUCT rule $\argmax_a\brack{Q(s, a) + c\,P(s, a)\sqrt{N(s)}/(1 + N(s, a))}$, which
  focuses exploration on moves the network rates as likely. Leaves are evaluated by $v$, not by rollouts.
- **Training.** After each self-play game with outcome $z \in \set{-1, 0, 1}$, the network is trained on every
  position $s$ to predict the outcome and the search's visit distribution $\pivec_s$:
  $(z - v)^2 - \pivec_s\transpose\log\pvec + c\norm{\thetavec}^2$.

This is <NoteLink to="policy-iteration">policy iteration</NoteLink> with search as the improvement operator. The visit
distribution of MCTS is a better policy than the network's prior, and training the network towards it improves the
prior used in the next search. AlphaZero reached superhuman play in chess, shogi and Go with the same algorithm
<Cite id="silver2018" />.

**MuZero** removes the need for known rules. It learns three functions: a representation $h$ from observations to a
latent state, a dynamics function $g$ from a latent state and action to the next latent state and a reward, and a
prediction function $f$ from a latent state to a policy and value. MCTS runs inside the latent model. The model is
trained end to end to predict, $k$ steps ahead of each real state, the observed rewards, the search policies and the
value targets; it is never trained to reconstruct observations <Cite id="schrittwieser2020" />. A model only has to be
right about what planning uses, and MuZero learns exactly that. It matched AlphaZero in board games and set the state
of the art on Atari.

## Worked example

A UCT node has been visited $N(s) = 100$ times. Action $a$ has mean value 0.6 from 40 visits; action $b$ has mean
value 0.5 from 10 visits. With $c = \sqrt 2$ and $\ln 100 = 4.605$:

- $a$: $0.6 + \sqrt 2\sqrt{4.605/40} = 0.6 + 0.48 = 1.08$;
- $b$: $0.5 + \sqrt 2\sqrt{4.605/10} = 0.5 + 0.96 = 1.46$.

The search explores $b$ next, although its mean is lower, because 10 visits leave its value uncertain.

**Compounding error.** With one-step error $\varepsilon = 0.01$ and $\gamma = 0.9$, the bound on the return error is
$2 \cdot 0.9 \cdot 0.01\,R_{\max}/0.01 = 1.8\,R_{\max}$, a fifth of the largest possible return $10\,R_{\max}$. With
$\gamma = 0.99$ the bound is $198\,R_{\max}$, larger than the largest possible return of $100\,R_{\max}$: a model with 1%
one-step error says nothing useful about long-horizon returns.

## Pitfalls

- **Model exploitation.** Planning maximises over the model's errors. Ensembles of models and penalties for model
  uncertainty keep the planner in regions where the model is trustworthy.
- **Objective mismatch.** A model trained to predict observations spends capacity on details, such as background
  pixels, that do not affect decisions.
- **Changing environments.** A tabular model that is never revisited stays wrong after the environment changes; Dyna
  variants add exploration bonuses for long-untried actions.
