<Definition>
A **domain** $\Dcal = \set{\Xcal, p(\xvec)}$ is an input space $\Xcal$ with a marginal distribution $p(\xvec)$ over it. A
**task** $\Tcal = \set{\Ycal, f}$ is an output space $\Ycal$ with a predictive function $f : \Xcal \to \Ycal$, which
in probabilistic terms is the conditional $p(y \mid \xvec)$. Given a source domain $\Dcal_S$ with task $\Tcal_S$ and a
target domain $\Dcal_T$ with task $\Tcal_T$, **transfer learning** aims to improve the learning of the target
function $f_T$ using knowledge from $\Dcal_S$ and $\Tcal_S$, where $\Dcal_S \ne \Dcal_T$ or $\Tcal_S \ne \Tcal_T$
<Cite id="pan2010survey" />.
</Definition>

## What can differ

The definition leaves four things free to change between source and target.

- **Input space**, $\Xcal_S \ne \Xcal_T$: the two domains are described by different features, such as images and
  text, or two smart homes with different sensors. Transfer across different input spaces is **heterogeneous**;
  transfer within one input space is **homogeneous** <Cite id="weiss2016survey" />.
- **Marginal distribution**, $p_S(\xvec) \ne p_T(\xvec)$ with the same $\Xcal$: the inputs are distributed
  differently, as in <NoteLink to="dataset-shift">covariate shift</NoteLink>.
- **Output space**, $\Ycal_S \ne \Ycal_T$: the tasks predict different things, such as 1000 object classes in the
  source and 5 disease grades in the target.
- **Conditional distribution**, $p_S(y \mid \xvec) \ne p_T(y \mid \xvec)$: the same input means something different,
  as when two annotators use one label differently.

A single learning problem with one distribution for training and testing is the special case in which none of these
differ.

## The three settings

Pan and Yang classify transfer problems by whether the task changes and where labelled data exist
<Cite id="pan2010survey" />.

**Inductive transfer** needs some labelled target data, because the target task has to be specified. **Transductive
transfer** keeps the task and changes the domain; the target provides unlabelled inputs only. The name follows the
older use of *transductive* for methods that see the test inputs during training. Unsupervised domain adaptation is the
main transductive problem. **Unsupervised transfer** has no labels anywhere and is the least studied of the three.

Later surveys add the distinction between homogeneous and heterogeneous transfer, and between a single source and
several <Cite id="weiss2016survey" /> <Cite id="zhuang2021survey" />. Multi-task learning is inductive transfer in
which every task is a target and all are learnt together <Cite id="caruana1997" />.

## What is transferred

Methods also differ in the form in which knowledge moves from source to target <Cite id="pan2010survey" />.

1. **Instances.** Source examples are reused in the target problem after reweighting. If the target and source share
   $p(y \mid \xvec)$, weighting each source example by $p_T(\xvec) / p_S(\xvec)$ turns the source risk into an
   unbiased estimate of the target risk. See <NoteLink to="importance-weighting-for-covariate-shift" />.
2. **Feature representations.** A map $\phivec : \Xcal \to \Zcal$ is learnt under which the domains look alike or the
   tasks share structure. See <NoteLink to="feature-alignment-methods" />, <NoteLink to="domain-adversarial-training" />
   and <NoteLink to="multi-task-learning" />.
3. **Parameters.** The source and target models share parameters, or the source parameters become a prior or a
   starting point for the target. Fine-tuning a pretrained network, hierarchical Bayesian priors and meta-learned
   initialisations all transfer parameters. See <NoteLink to="transfer-learning-and-fine-tuning" />, <NoteLink
   to="hierarchical-bayesian-transfer" /> and <NoteLink to="meta-learning" />.
4. **Relations.** Relational structure, such as which entities interact, is mapped from one domain to another. This
   form applies to relational data such as social networks, and has the fewest methods.

## When transfer fails

Transfer is not guaranteed to help. **Negative transfer** is the case in which using the source makes the target
learner worse than ignoring it <Cite id="wang2019negative" />. It happens when the source and target are too unlike,
when the method assumes the wrong kind of similarity, or when target data are plentiful enough that the source adds
only bias. The domain-adaptation bound of Ben-David et al. makes the trade-off explicit: target error is at most source
error plus a divergence between the domains plus the error of the best joint hypothesis <Cite id="bendavid2007" />.
Each of the three can be large. See <NoteLink to="negative-transfer" /> and <NoteLink to="when-does-transfer-help" />.

## Where the chapters sit

- **Foundations.** <NoteLink to="negative-transfer" /> and <NoteLink to="when-does-transfer-help" /> cover the
  conditions under which borrowing from a source pays.
- **Domain adaptation.** <NoteLink to="domain-adaptation-theory" /> derives the target-error bound.
  <NoteLink to="importance-weighting-for-covariate-shift" />, <NoteLink to="feature-alignment-methods" /> and
  <NoteLink to="domain-adversarial-training" /> are the three main families of methods. <NoteLink
  to="domain-generalisation" /> removes the target data altogether, and <NoteLink to="label-shift-and-target-shift" />
  handles a change in the class balance.
- **Multi-task and meta-learning.** <NoteLink to="multi-task-learning" /> and <NoteLink
  to="hierarchical-bayesian-transfer" /> share structure across tasks learnt together. <NoteLink to="meta-learning" />,
  <NoteLink to="metric-based-few-shot-learning" /> and <NoteLink to="few-shot-learning-evaluation" /> learn how to
  learn a new task from few examples.
- **Active and Bayesian transfer.** <NoteLink to="active-transfer-learning" />, <NoteLink
  to="bayesian-active-learning" /> and <NoteLink to="context-modulation-and-sensor-transfer" /> combine a transferred
  model with a budget of target labels, with activity recognition in smart homes as the running application.
- **Online transfer.** <NoteLink to="online-transfer-learning" />, <NoteLink to="test-time-adaptation" /> and
  <NoteLink to="lifelong-and-continual-transfer" /> treat target data that arrive as a stream. The general theory of learning from
  streams is in <NoteLink to="online-learning" />.

Fine-tuning of pretrained networks and parameter-efficient methods such as LoRA are covered in <NoteLink
to="transfer-learning-and-fine-tuning" />. The empirical side of distribution shift, including benchmarks, is covered in
<NoteLink to="robustness-to-distribution-shift" />.
