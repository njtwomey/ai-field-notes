<Definition>
A **field-aware ranking model** scores a document made of several fields $f_1, \ldots, f_k$, such as title, description
and ingredients, against a query $q$ by modelling **interactions** between representations of the query and the fields.
Query–field interactions pair the query with each field ($k$ pairs). All-pairs interactions also pair fields with each
other, $\binom{k+1}{2} = k(k+1)/2$ pairs among the query and $k$ fields <Cite id="takiguchi2021recipe" />.
</Definition>

## Intuition

Documents have structure. A recipe has a title, an ingredient list, a description, a country and a photo. Collapsing
all fields into one text or one embedding discards which field matched the query and how the fields relate to each
other <Cite id="takiguchi2021recipe" />. A query for "quick chicken soup" matching the title is stronger evidence than
the same words buried in the description.

Keeping fields apart requires choosing which pairs of representations interact. Pairing only the query
with each field encodes the classical retrieval view, in which relevance is a match between the query and the document.
Pairing every field with every other field, as click-prediction models do, also lets the model learn document-side
regularities, such as recipes whose title and country agree being more popular. The all-pairs choice is more expressive
and grows quadratically. With a query and six fields it has 21 interactions against 6 for query–field pairs. Most of the
extra 15 pairs, such as description–photo, carry little signal about a click, and each one adds parameters to fit and
noise to the score.

## Two model families

Two neural designs keep the fields apart and differ in how they combine interactions.

- **NRM-F** (neural ranking model with multiple fields) encodes each field and the query separately, forms query–field
  interactions by element-wise (Hadamard) products, concatenates them and scores them with fully connected layers
  <Cite id="zamani2018nrmf" />. It was designed for document ranking and is built around the query.
- **FwFM**, the <NoteLink to="field-weighted-factorisation-machines">field-weighted factorisation machine</NoteLink>
  from click prediction, treats the query and each field as fields of one input. It scores each pair by the dot product
  of the two embeddings times a learned weight for that pair of fields, adds first-order terms, and sums
  <Cite id="pan2018fwfm" />. It does not distinguish the query from any other field.

Both designs can be restricted to query–field pairs or given all pairs, which separates the choice of interactions from
the choice of architecture. In an FwFM, restricting to query–field pairs amounts to fixing the weight $r$ of every
field–field pair at zero.

## What the evidence shows

Takiguchi, Twomey and Vaquero compared these choices on search logs from Cookpad, a recipe platform, with clicked recipes
as positives and <NoteLink to="normalised-discounted-cumulative-gain">NDCG@20</NoteLink> as the metric <Cite id="takiguchi2020fields" />. In both
architectures the query–field restriction beat the all-pairs version, by a small but statistically significant margin.
The FwFM beat NRM-F, so a model from recommendation served document ranking without modification. A follow-up study that
added image embeddings found the same ordering, with the query–field FwFM best overall <Cite id="takiguchi2021recipe" />.

The same study correlated each interaction's score with clicks. Query pairs ranked low and title–country ranked highest
<Cite id="takiguchi2021recipe" />. The candidates had already been retrieved because they matched the query, so at the
re-ranking stage the query adds little that the candidate set does not already encode, while regional preference
distinguishes candidates strongly. Image pairs were weak, which made the costly image features a candidate for removal.
A model on a small set of correlation-selected pairs matched the query–field model and beat the all-pairs model. Such
selection matters where there is no query at all, as in re-ranking a recipe feed.

## Lessons

- **More interactions can be worse.** The query–field subset beat the exhaustive set in both architectures, and a
  subset selected by interaction–click correlation also beat it. Modelling every pair invites noise and correlated
  features.
- **Architecture matters too.** The FwFM beat NRM-F <Cite id="takiguchi2020fields" />. The query–field restriction beat
  all pairs in both architectures, so that conclusion transferred between them.

- **Explainability.** A model factorised by fields gives a score per field pair, which mirrors the document's structure
  <Cite id="takiguchi2021recipe" />.

## Assumptions

- Fields are known and consistent across documents. Free text with no field boundaries needs a different model.
- Clicks are a usable relevance signal. <Gloss name="position-bias">Position bias</Gloss> and presentation effects enter the labels unless corrected.

## Pitfalls

- **Truncated sessions inflate baselines.** Cutting each session at the last click makes even a random ranking score
  an NDCG@20 of about 0.52 in the recipe study <Cite id="takiguchi2021recipe" />. Compare against random and simple
  baselines under the same protocol.
- **Correlation is not importance.** Interaction–click correlations are a heuristic for choosing pairs; a pair with low
  marginal correlation can still help in combination with others.
