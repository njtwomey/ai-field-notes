<Definition>
**LLMs as recommenders** covers two uses of pre-trained large language models. In the **discriminative** use (DLLM4Rec),
an LLM encodes item or user text into embeddings consumed by a conventional recommender. In the **generative** use
(GLLM4Rec), the LLM itself produces recommendations as text, from a prompt holding the user's history and an instruction
<Cite id="wu2024llmrecsurvey" />.
</Definition>

## Premise

Item identifiers can be treated as language. A title, a description or a sequence of ID tokens is text, so the machinery
of language modelling applies to recommendation. A model pre-trained on the web also arrives knowing a great deal about
films, books and products, knowledge that a collaborative model has to learn from interactions.

## Adapting an LLM

Three techniques are common.

- **Prompting.** Give the model the user's history and an instruction, such as "Here is a user's viewing history.
  Recommend five similar films", without changing its weights. Hou et al. found that LLMs used this way are competitive
  zero-shot rankers of candidate lists, but that they are sensitive to the order of candidates in the prompt and
  favour popular items <Cite id="hou2024llmrank" />. See <NoteLink to="prompting">prompting</NoteLink>.
- **Fine-tuning.** Continue training on the domain's interaction data, so the model learns which items follow which in
  user histories.
- **Instruction tuning.** Fine-tune on many instructions and desired outputs for recommendation tasks. TALLRec showed
  that lightweight tuning on a small number of examples aligns an LLM with a recommendation task far better than
  in-context examples alone <Cite id="bao2023tallrec" />. See <NoteLink
  to="instruction-tuning-and-alignment">instruction tuning</NoteLink>.

## Uses along a spectrum

- **Feature extractor.** An LLM encodes each item's text into a rich embedding, used by the item tower of a
  <NoteLink to="two-tower-model">two-tower model</NoteLink> or a ranker. This is the most common deployment.
- **Zero-shot recommender.** A request such as "science-fiction films like *Blade Runner* but more optimistic" can be
  answered with no history at all, from knowledge in the weights.
- **End-to-end generator.** The LLM generates item identifiers, as in
  <NoteLink to="generative-retrieval-for-recommendation">generative retrieval</NoteLink>, or text-to-text multi-task
  models such as P5 <Cite id="geng2022p5" />.

## Cold start

LLMs are the latest step in <NoteLink to="content-based-filtering">content-based filtering</NoteLink> and perhaps the
strongest answer to item cold start so far. An LLM can infer that people who like *The Matrix* will like *Blade Runner*
without seeing co-interactions, because it knows both are about cyberpunk, artificial intelligence and dystopia. A new
item with only a description can be placed near the items users would treat as similar, approximating the collaborative
embedding it would eventually learn. See the <NoteLink to="cold-start-problem">cold-start problem</NoteLink>.

## Opportunities and challenges



**Opportunities.**

- **Conversation.** The user can refine a request in dialogue ("a thriller, but not too violent").
- **Explanations.** The model can say why it recommends an item, which can raise trust.
- **World knowledge.** Semantic relations in descriptions and reviews are available without interaction data.

**Challenges.**

- **Hallucination.** The model can recommend items that do not exist or are unavailable. Outputs must be grounded in the
  catalogue. See <NoteLink to="hallucination-and-faithfulness">hallucination</NoteLink>.
- **Latency and cost.** Running a multi-billion-parameter model per request at web scale needs distillation,
  quantisation and specialised serving.
- **Precision.** Language is vague; a recommendation needs an exact item.

The generative interface changes the problem itself. A list shows what; a conversation can explain why and let the user
steer. Success becomes a satisfactory conversation, not a correctly ordered list, which also changes how systems are
evaluated (see <NoteLink to="language-model-as-a-judge">LLM as a judge</NoteLink>).

## Pitfalls

- **Benchmark contamination.** Public datasets such as MovieLens may be in the pre-training data. Zero-shot results on
  them can overstate performance.
- **Inherited bias.** Pre-training data over-represent popular items and dominant cultures, and LLM recommenders
  reproduce this.
