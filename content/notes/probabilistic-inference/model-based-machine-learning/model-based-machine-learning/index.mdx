<Definition>
**Model-based machine learning** (MBML) builds a probabilistic model tailored to one application instead of choosing a
standard algorithm and adapting the data to it. The modeller writes down assumptions about how the data were
generated, expresses them as a factor graph of <NoteLink to="random-variable">random variables</NoteLink> and factors, and hands the graph to a general
inference engine that computes posteriors by message passing <Cite id="bishop2013mbml" />. The same engine serves every
model; only the model changes.
</Definition>

## The philosophy

Traditional machine learning offers a toolbox: <NoteLink to="logistic-regression">logistic regression</NoteLink>, <Gloss name="svm">support vector machines</Gloss>, <NoteLink to="random-forest">random forests</NoteLink>, neural
networks. Each tool fixes a set of assumptions, often implicit, and the practitioner picks the tool whose assumptions
fit best. Model-based machine learning reverses this <Cite id="winn2023intro" />:

- **The model is the design artefact.** Each assumption is stated in words, then as a factor. A disagreement about the
  output is a disagreement about a listed assumption, which can be tested and changed.
- **Inference is generic.** Given the factor graph, message passing, whether <Gloss name="bp">belief propagation</Gloss>, <Gloss name="ep">expectation
  propagation</Gloss> or variational message passing, computes the posteriors. No algorithm is derived by hand for the problem.
- **Uncertainty is kept.** Every unknown has a distribution. Predictions carry calibrated uncertainty, and <NoteLink to="online-learning">online
  learning</NoteLink> is the posterior of one batch becoming the prior of the next.
- **Many standard methods are special cases.** Chapter 8 of the book reads LDA, <Gloss name="pca" />, k-means and <NoteLink to="decision-tree">decision trees</NoteLink> as
  models with particular assumptions; <NoteLink to="matchbox-recommender">Matchbox</NoteLink> contains matrix
  factorisation as a special case.

## The workflow

The book's interlude on the machine learning life cycle lists eight stages <Cite id="winn2023lifecycle" />:

1. **Gather data** for training and for evaluation.
2. **Collect domain knowledge** that supports the modelling assumptions.
3. **Visualise the data** to understand it and find problems.
4. **Build the model**: write the assumptions, one quantity at a time, and turn each into a factor or the absence of an
   edge.
5. **Perform inference** to predict the variables of interest.
6. **Evaluate** the results against a metric and a success criterion.
7. **Diagnose** what limits accuracy, using visualisation and synthetic data sampled from the model.
8. **Refine** the data, the model, the inference or the evaluation, and return to step 5.

The last two stages repeat until the system is good enough. Each case study goes through the loop several times, and
its failures, traced back to a named assumption, are as instructive as its final model.

## When it fits

Model-based design suits problems where domain knowledge is strong, data are scarce or arrive over time, uncertainty
matters, and the result must be explained. It suits less well problems where the input is raw and high-dimensional,
such as images or audio, and the useful structure is unknown; there, learned representations do better, and a model can
sit on top of them. Writing a good model also takes skill: the assumptions must be both true enough and tractable for
message passing.
