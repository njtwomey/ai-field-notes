<Definition>
Let a function of variables $\xvec = (x_1, \dots, x_n)$ factorise as

$$
p(\xvec) = \frac{1}{Z} \prod_{a=1}^{m} f_a(\xvec_{\partial a}),
$$

where each factor $f_a \ge 0$ depends on a subset $\partial a$ of the variables. Its **factor graph** is the bipartite
graph with a variable node for each $x_i$, a factor node for each $f_a$, and an edge between $x_i$ and $f_a$ exactly
when $i \in \partial a$ <Cite id="kschischang2001" />. The neighbours of variable $i$ are the factors that use it,
written $\partial i$.
</Definition>

## Why a separate graph

A Markov random field records which variables interact, not how. Consider three variables that are all joined to each
other. The undirected graph is a triangle, and it fits both of these distributions:

$$
p(\xvec) \propto f_{12}(x_1, x_2)\, f_{23}(x_2, x_3)\, f_{13}(x_1, x_3)
\qquad\text{and}\qquad
p(\xvec) \propto f_{123}(x_1, x_2, x_3).
$$

With $k$ states per variable, the first has $3k^2$ table entries and the second $k^3$. For $k = 10$ that is 300
against 1000. The factor graphs differ: the first has three factor nodes, each joined to two variables, and the
second has one factor node joined to all three. The factor graph states the model's actual parameterisation, and it
states the actual cost of inference, since message passing works with each factor's table.

## Converting other graphs

- **From a Bayesian network.** Add one factor per <NoteLink to="conditional-probability">conditional distribution</NoteLink>, $f_i = p(x_i \mid \xvec_{\mathrm{pa}(i)})$,
  joined to $x_i$ and its parents. Then $Z = 1$. See <NoteLink to="bayesian-network">Bayesian network</NoteLink>.
- **From a Markov random field.** Add one factor per clique potential, joined to the variables of the clique. See
  <NoteLink to="markov-random-field">Markov random field</NoteLink>.
- **Evidence.** Observing $x_j = v$ multiplies in the indicator factor $\indicator[x_j = v]$, or equivalently fixes
  $x_j$ in every factor that uses it and deletes the variable node. The same graph then represents the posterior.

<NoteLink to="independence">Independences</NoteLink> are read from a factor graph by separation, as in an undirected graph: if every path between two sets of
variables passes through a set $S$ of observed variables, the two sets are conditionally independent given $S$. The
argument is the same as for Markov random fields, since each factor lies entirely on one side of $S$.

## Trees and cycles

Many exact inference algorithms need a tree. A factor graph can be a tree when the corresponding undirected graph is
not.

**Example.** Take the collider $a \to c \leftarrow b$ with an extra child $d$ of $c$. Its moral graph joins $a$ and
$b$, which creates the cycle $a - b - c - a$. Its factor graph has four factor nodes, $p(a)$, $p(b)$,
$p(c \mid a, b)$ and $p(d \mid c)$. The factor $p(c \mid a, b)$ joins $a$, $b$ and $c$ without creating a cycle, because
the three variables connect through one factor node rather than through three pairwise edges. The factor graph is a
tree. More generally, the factor graph of any polytree, a directed graph with no undirected cycles, is a tree
<Cite id="bishop2006" />.

On a tree-structured factor graph, <NoteLink to="belief-propagation">belief propagation</NoteLink> computes every
marginal exactly with two sweeps of messages. On a graph with cycles, the same local messages give
<NoteLink to="loopy-belief-propagation">loopy belief propagation</NoteLink>, an approximation. Exact inference on a
cyclic graph groups variables into clusters until the cluster graph is a tree, as in the
<NoteLink to="junction-tree-algorithm">junction tree algorithm</NoteLink>.

Factor graphs also carry continuous models: the <NoteLink to="trueskill">TrueSkill</NoteLink> rating system is a factor
graph of skills, performances and outcomes, with Gaussian messages everywhere except at the outcome factors.

## Worked example: a hidden Markov model

A <NoteLink to="hidden-markov-model">hidden Markov model</NoteLink> with hidden states $y_1, \dots, y_N$ and observations
$x_1, \dots, x_N$ has the joint distribution

$$
p(\xvec, \yvec) = p(y_1) \prod_{n=2}^{N} p(y_n \mid y_{n-1}) \prod_{n=1}^{N} p(x_n \mid y_n).
$$

With the observations fixed, each emission $p(x_n \mid y_n)$ is a factor on $y_n$ alone. Absorb it, and $p(y_1)$, into a
node factor $\psi_n(y_n)$. The factor graph is then a chain: variable nodes $y_1, \dots, y_N$, a node factor hanging
off each, and one pairwise factor $\Psi_n(y_n, y_{n+1}) = p(y_{n+1} \mid y_n)$ between neighbours. It has $2N - 1$
factor nodes and no cycles. Sum-product on this chain is the <Gloss name="forward-backward">forward–backward algorithm</Gloss>, and max-product is the
<Gloss name="viterbi">Viterbi algorithm</Gloss>. A second-order model, with $p(y_n \mid y_{n-1}, y_{n-2})$, needs factors joined to three states, and
its factor graph has cycles unless consecutive pairs of states are merged into single variables.

## Pitfalls

- **Normalisation.** A factor graph describes an unnormalised product. $Z$ is 1 for a Bayesian network, but in general it
  must be computed, and computing it is an inference problem.
- **Merging factors hides structure.** Multiplying several factors into one is always valid, and can turn a cyclic graph
  into a tree. The merged factor's table grows exponentially in the number of variables it touches, which is where the
  cost of exact inference reappears.
