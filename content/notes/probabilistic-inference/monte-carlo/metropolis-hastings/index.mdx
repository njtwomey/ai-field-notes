<Definition>
The Metropolis–Hastings algorithm builds a <NoteLink to="markov-chain">Markov chain</NoteLink> with stationary distribution $\pi$ from any proposal
distribution $q(y \mid x)$. At state $x$ it draws a candidate $y \sim q(\cdot \mid x)$ and moves to $y$ with probability

$$
\alpha(x, y) = \min\set{1,\ \frac{\pi(y)\, q(x \mid y)}{\pi(x)\, q(y \mid x)}};
$$

otherwise the chain stays at $x$ and records $x$ again. The ratio uses $\pi$ only through $\pi(y)/\pi(x)$, so the
normalising constant of $\pi$ is never needed <Cite id="metropolis1953" /> <Cite id="hastings1970" />.
</Definition>

## Problem

<NoteLink to="markov-chain-monte-carlo">Markov chain Monte Carlo</NoteLink> needs a transition kernel that leaves the
target invariant. Designing one directly is hard. Proposing moves is easy: a Gaussian step from the current point
will do. Metropolis–Hastings turns any proposal into a valid kernel by accepting or rejecting its moves, with the
acceptance probability chosen so that detailed balance holds.

## Deriving the acceptance probability

The kernel moves from $x$ to $y \ne x$ with density $T(x \to y) = q(y \mid x)\, \alpha(x, y)$: propose $y$, then
accept. Rejected proposals add to the probability of staying at $x$. Detailed balance, which implies stationarity,
requires for every pair $x \ne y$

$$
\pi(x)\, q(y \mid x)\, \alpha(x, y) = \pi(y)\, q(x \mid y)\, \alpha(y, x).
$$

The case $x = y$ holds trivially, since both sides are the same. Rearranged, the condition fixes the ratio of the two
acceptance probabilities:

$$
\frac{\alpha(x, y)}{\alpha(y, x)} = \frac{\pi(y)\, q(x \mid y)}{\pi(x)\, q(y \mid x)} \eqdef r(x, y).
$$

Note that $r(y, x) = 1/r(x, y)$. Any pair of probabilities in $[0, 1]$ with this ratio works. To reject as rarely as
possible, set the larger of the two to 1:

- If $r(x, y) \ge 1$, set $\alpha(x, y) = 1$ and $\alpha(y, x) = 1/r(x, y) = r(y, x)$.
- If $r(x, y) < 1$, set $\alpha(x, y) = r(x, y)$ and $\alpha(y, x) = 1$.

Both cases are $\alpha(x, y) = \min\set{1, r(x, y)}$, which is the Metropolis–Hastings rule. Any other valid choice
multiplies both probabilities by a factor below 1 and rejects more often. The ratio $r$ has two parts. The target ratio
$\pi(y)/\pi(x)$ pulls the chain towards high density. The proposal ratio $q(x \mid y)/q(y \mid x)$, the Hastings
correction, removes the bias of a proposal that prefers some directions.

Stationarity is only half of what is needed. The chain must also be ergodic, which holds for example when
$q(y \mid x) > 0$ for all $x$ and $y$ in the support of $\pi$ <Cite id="tierney1994" />.

## The algorithm

Starting from any $x_0$ with $\pi(x_0) > 0$, for $t = 0, 1, 2, \dots$:

1. Propose $y \sim q(\cdot \mid x_t)$.
2. Compute $\log r = \log\tilde\pi(y) - \log\tilde\pi(x_t) + \log q(x_t \mid y) - \log q(y \mid x_t)$, where
   $\tilde\pi$ is the unnormalised target.
3. Draw $u \sim \Unif(0, 1)$. If $\log u < \log r$, set $x_{t+1} = y$; otherwise set $x_{t+1} = x_t$.

A rejected proposal repeats the current state in the output. Dropping repeats biases the sample towards
low-probability states, because repeats are how the chain spends extra time where $\pi$ is high.

## Common proposals

- **<NoteLink to="random-walk">Random-walk</NoteLink> Metropolis.** $y = x + \epsilon$ with $\epsilon \sim \Gauss(\zeros, \sigma^2\eye)$. The proposal is
  symmetric, $q(y \mid x) = q(x \mid y)$, so the Hastings correction cancels and $\alpha = \min\set{1, \pi(y)/\pi(x)}$.
  This is the original algorithm of Metropolis et al. <Cite id="metropolis1953" />. Moves uphill are always accepted;
  moves downhill are accepted with probability equal to the density ratio.
- **<NoteLink to="independence">Independence</NoteLink> sampler.** $q(y \mid x) = g(y)$ ignores the current state. The acceptance ratio becomes
  $\frac{\pi(y)/g(y)}{\pi(x)/g(x)}$, a ratio of <NoteLink to="importance-sampling">importance weights</NoteLink>. It works
  well only when $g$ is close to $\pi$ and has heavier tails.
- **Langevin proposals** (MALA) shift the random walk along the <NoteLink to="gradient">gradient</NoteLink>:
  $y = x + \frac{\sigma^2}{2}\nabla\log\pi(x) + \sigma\epsilon$. The proposal is asymmetric, so the Hastings
  correction is needed. <NoteLink to="langevin-dynamics">Langevin dynamics</NoteLink> derives this proposal and its
  acceptance ratio.
  <NoteLink to="hamiltonian-monte-carlo">Hamiltonian Monte Carlo</NoteLink> takes many gradient steps per proposal.

## Tuning the step size

The random-walk scale $\sigma$ controls a trade-off. With small $\sigma$, almost every proposal is accepted, but the
chain moves a distance of order $\sigma$ per step and explores by a slow random walk. With large $\sigma$, most
proposals land where $\pi$ is small and are rejected, so the chain sits still. Both extremes give highly correlated
samples. For targets that are products of $d$ identical components, the efficiency is maximised as $d \to \infty$ at an
acceptance rate of 0.234, with $\sigma \approx 2.38/\sqrt{d}$ times the target's scale <Cite id="roberts1997" />. In one
dimension the optimum is near 0.44. The $1/\sqrt{d}$ scaling means that random-walk Metropolis needs a number of steps
that grows linearly with the dimension to move a fixed distance.

## Worked example: a three-state target

Let $\pi = (0.5, 0.3, 0.2)$ on states $\set{1, 2, 3}$. From any state, propose each of the other two states with
probability $1/2$. The proposal is symmetric, so a move from $i$ to $j$ is accepted with probability
$\min\set{1, \pi_j/\pi_i}$.

- From state 1, moves to 2 and 3 are downhill: $T_{12} = \frac12 \times \frac{0.3}{0.5} = 0.3$ and
  $T_{13} = \frac12 \times \frac{0.2}{0.5} = 0.2$, so $T_{11} = 0.5$.
- From state 2, the move to 1 is uphill and always accepted: $T_{21} = 0.5$. The move to 3 has
  $T_{23} = \frac12 \times \frac{0.2}{0.3} = \frac13$, so $T_{22} = \frac16$.
- From state 3, both moves are uphill: $T_{31} = T_{32} = 0.5$ and $T_{33} = 0$.

Detailed balance holds pair by pair: $\pi_1 T_{12} = 0.5 \times 0.3 = 0.15 = 0.3 \times 0.5 = \pi_2 T_{21}$,
$\pi_1 T_{13} = 0.1 = \pi_3 T_{31}$, and $\pi_2 T_{23} = 0.1 = \pi_3 T_{32}$. So $\pi T = \pi$. A chain started in state
3 has distribution $(0.5, 0.5, 0)$ after one step, $(0.5, 0.233, 0.267)$ after two and $(0.5, 0.322, 0.178)$ after
three. The eigenvalues of $T$ are $1$, $0$ and $-1/3$, so the error shrinks by a factor of 3 per step and changes sign
each time.

## Cost

Each step costs one evaluation of $\log\tilde\pi$ and one draw from the proposal. The number of steps needed depends on
the mixing time of the chain, which depends on the proposal, the dimension and the geometry of the target. Correlated
targets are hard for an isotropic random walk: the step size must suit the narrowest direction, so progress along the
widest direction is slow. Scaling the proposal by an estimate of the target covariance, obtained from a pilot run,
removes much of this.

## Trade-offs

- **Needs only density ratios.** No gradients, no normalising constant and no conjugacy. This generality makes it the
  default for small, awkward models and the building block of many other samplers.
- **Scales poorly with dimension.** The random walk needs $O(d)$ steps per effective sample in $d$ dimensions
  <Cite id="roberts1997" />. Hamiltonian Monte Carlo needs about $O(d^{1/4})$ gradient evaluations on smooth targets
  <Cite id="neal2011" />.
- **Multimodal targets.** A local proposal rarely crosses between well-separated modes. The chain can report one mode
  with every diagnostic looking healthy.
- **Rejections are data.** Keep the repeated states; they carry the weighting that makes the chain correct.
