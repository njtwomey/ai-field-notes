<Definition>
An <Gloss name="seq2seq">encoder–decoder</Gloss> transformer has two stacks. The **encoder** applies unmasked self-attention to the input tokens
$x_1, \dots, x_m$ and outputs one vector per input token. The **decoder** applies causal self-attention to the output
prefix $y_1, \dots, y_t$ and <NoteLink to="encoder-decoder-cross-attention">cross-attention</NoteLink> to the encoder
outputs, and predicts $y_{t+1}$. The model defines $p(\yvec \mid \xvec) = \prod_t p(y_{t+1} \mid y_{\le t}, \xvec)$. The
original <NoteLink to="transformer">transformer</NoteLink> has this form <Cite id="vaswani2017" />.
</Definition>

## Intuition

The input is read in full, with every input token seeing every other. The output is written left to right, and each
step can look up any part of the input through cross-attention. The division matches tasks with a distinct source and
target: translation, summarisation, or a question with its answer.

## Parameters and compute

Let each stack have $L$ layers, and write $P$ for the parameters of one $L$-layer stack. Ignoring cross-attention, the
encoder–decoder has $2P$ parameters. A <NoteLink to="decoder-only-transformers">decoder-only model</NoteLink> with $2L$ layers also has about $2P$.

Now count compute for one example with $m$ input and $n$ target tokens, at two <Gloss name="flop" plural /> per parameter per token. The
encoder runs only on the input and the decoder only on the target:

$$
C_{\text{enc-dec}} \approx 2P\,m + 2P\,n = 2P(m + n).
$$

A decoder-only model must run all of its layers on the concatenation of input and target. With $2L$ layers,
$C \approx 2 \cdot 2P\,(m + n)$, twice as much; with $L$ layers, $C \approx 2P(m + n)$, the same but with half the
parameters. So an $L + L$ encoder–decoder matches an $L$-layer decoder in compute and a $2L$-layer decoder in
parameters. T5 used this accounting to compare architectures fairly and observed nearly identical step times for the two
equal-compute cases. Cross-attention adds about 10% to the parameters at the sizes T5 studied <Cite id="raffel2020" />.

## T5

T5 casts every task as text to text: the input is a string with a task prefix, such as "translate English to German:",
and the output is a string <Cite id="raffel2020" />. Classification outputs the label as a word. The architecture is the
2017 encoder–decoder with pre-norm, a <NoteLink to="layer-normalisation">layer normalisation</NoteLink> without shift, and a learned <NoteLink to="t5-relative-position-bias">relative position bias</NoteLink> in place of sinusoids. Pre-training uses the
C4 corpus, about 750 GB of cleaned web text, and the largest model has 11 billion parameters.

**<NoteLink to="masked-language-modelling">Span corruption</NoteLink>.** 15% of the input tokens are chosen for corruption. Each run of consecutive corrupted tokens is
replaced by a single sentinel token, unique within the example. The target lists the removed spans, each preceded by its
sentinel, and ends with a final sentinel. The mean span length is 3 <Cite id="raffel2020" />.

**Architecture comparison.** Matched for compute per example, T5 reported <Cite id="raffel2020" />:

| Architecture                 | Objective          | Parameters | Compute | <Gloss name="glue" />  |
| ---------------------------- | ------------------ | ---------- | ------- | ----- |
| Encoder–decoder              | denoising          | $2P$       | $M$     | 83.28 |
| Encoder–decoder, shared      | denoising          | $P$        | $M$     | 82.81 |
| Encoder–decoder, $L/2 + L/2$ | denoising          | $P$        | $M/2$   | 80.88 |
| Prefix language model        | denoising          | $P$        | $M$     | 81.82 |
| Decoder <Gloss name="language-model">language model</Gloss>       | denoising          | $P$        | $M$     | 74.70 |
| Encoder–decoder              | language modelling | $2P$       | $M$     | 79.56 |

The encoder–decoder with denoising was best on every task. Sharing the weights of the two stacks cost little.

## BART

BART is a denoising autoencoder for sequences: corrupt a document, encode the corrupted version bidirectionally, and
train the decoder to reproduce the original <Cite id="lewis2020bart" />. Because the decoder regenerates the whole
document, any corruption can be used. Lewis et al. compared five:

- **token masking**: random tokens replaced by `[MASK]`;
- **token deletion**: random tokens removed, so the model must also find where input is missing;
- **text infilling**: spans with lengths drawn from a <NoteLink to="poisson-distribution">Poisson distribution</NoteLink> with $\lambda = 3$ are each replaced by one
  `[MASK]`, including spans of length 0, so the model must also predict how many tokens are missing;
- **sentence permutation**: the sentences of a document are shuffled;
- **document rotation**: the document is rotated to start at a random token.

Text infilling performed best across tasks, and document rotation and sentence shuffling alone performed poorly. The
final model combines text infilling with sentence permutation, masks 30% of tokens, and has 12 layers in each stack with
width 1024. On abstractive summarisation it improved on previous work by up to 6 <Gloss name="rouge" /> points <Cite id="lewis2020bart" />.

## Worked example

Take the sentence "Thank you for inviting me to your party last week ." as 11 tokens, with "for", "inviting" and "last"
chosen for corruption <Cite id="raffel2020" />. "for inviting" is one run, so it becomes one sentinel.

- Input: `Thank you <X> me to your party <Y> week .` (10 tokens).
- Target: `<X> for inviting <Y> last <Z>` (6 tokens).

The decoder predicts 6 tokens. A <NoteLink to="autoregressive-transformer-language-model">decoder-only language model</NoteLink> on the original sentence would predict 10. The encoder
still reads 10 tokens, but reading costs the same whether or not a token is a target.

**Compute.** For T5's pre-training shapes of $m = 512$ input and $n = 114$ target tokens <Cite id="shazeer2020" />, an
$L + L$ encoder–decoder with $P$ parameters per stack costs about $2P \times 626$ FLOPs per example. A $2L$-layer
decoder with the same total parameters, run on the 626 concatenated tokens, costs about $4P \times 626$.

## Where encoder–decoders are used

<Gloss name="machine-translation">Machine translation</Gloss>, summarisation and other conditional generation with a clearly separated input keep this form. The UL2 authors
give the "soft advice" to default to an encoder–decoder, and trained their 20B model as one, with 32 layers in each
stack <Cite id="tay2023ul2" />. The same connectivity can be obtained in a single stack with a prefix mask; see <NoteLink to="prefix-language-models-and-unified-models">prefix language models</NoteLink>.

## Assumptions

- The input is fixed before generation begins. If the input grows, as in a conversation, the encoder must re-read it.
- Input and output are distinct. For open-ended continuation, the split between them is arbitrary.

## Pitfalls

- **Comparing by parameters alone.** An encoder–decoder with the parameters of a decoder costs about half as much
  compute per example. Comparisons must say which quantity is held fixed.
- **Cross-attention cost at inference.** Every <NoteLink to="modern-decoder-block">decoder layer</NoteLink> attends to all $m$ encoder outputs at every step. Their keys
  and values are computed once per input and cached, but they occupy memory in every layer.
