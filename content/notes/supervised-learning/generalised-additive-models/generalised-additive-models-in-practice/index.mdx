<Definition>
This note maps the Python package pyGAM <Cite id="serven2018" /> onto the R package mgcv <Cite id="wood2017" />. Both
fit <Gloss name="gam">generalised additive models</Gloss>: sums of
<NoteLink to="smoothing-and-penalised-splines">penalised spline</NoteLink> terms under a <Gloss name="glm" /> family and
link.
</Definition>

## Problem

The two packages fit the same model and differ in defaults that change the answer. The main differences are:

- **Basis.** pyGAM uses <NoteLink to="p-splines">P-splines</NoteLink>: 20 cubic
  <NoteLink to="b-splines">B-splines</NoteLink> with a second-difference penalty. mgcv's default is a thin-plate
  regression spline with $k = 10$ and the $\int f''^2$ penalty.
- **Smoothing parameters.** pyGAM searches a grid for the lowest <Gloss name="gcv" /> or <Gloss name="ubre" />. mgcv
  optimises GCV by default and <Gloss name="reml" /> on request, by <NoteLink to="newtons-method">Newton's
  method</NoteLink> over $\log\lambda$.
- **Identifiability.** mgcv centres every smooth. pyGAM does not, so its term curves carry arbitrary offsets.
- **Intervals and tests.** mgcv's intervals use the Bayesian covariance $\Vmat_\beta$ and its
  <NoteLink to="p-value">p-values</NoteLink> use Wood's reduced-rank test. pyGAM's intervals use the frequentist
  covariance, and its p-values are known to be too small.

## Mechanism

### Mapping pyGAM onto mgcv

| Purpose | pyGAM | mgcv |
| --- | --- | --- |
| Gaussian response | `LinearGAM` | `gam(y ~ ..., family = gaussian())` |
| Binary response | `LogisticGAM` | `family = binomial` |
| Counts | `PoissonGAM` | `family = poisson`, or `nb()` for overdispersion |
| Positive continuous | `GammaGAM` (log link) | `family = Gamma(link = "log")` |
| Positive, heavy right tail | `InvGaussGAM` (log link) | `family = inverse.gaussian(link = "log")` |
| Conditional expectile | `ExpectileGAM(expectile=0.9)` | not in mgcv |
| Any family and link | `GAM(distribution=..., link=...)` | any `family` object |
| Smooth of a numeric feature | `s(0, n_splines=20, spline_order=3)` | `s(x, k = 10, bs = "tp")` |
| P-spline basis | `s(0)` (the default) | `s(x, bs = "ps")` |
| Cyclic smooth | `s(0, basis="cp", edge_knots=[0, 24])` | `s(x, bs = "cc")` with `knots = list(x = c(0, 24))` |
| Linear term | `l(0)` | `x` |
| Factor | `f(0)`, one coefficient per level, ridge-penalised | `g` (unpenalised), or `s(g, bs = "re")` (random effect) |
| Smooth interaction | `te(0, 1)` | `te(x, z)`, or `ti(x, z)` for the pure interaction |
| Varying coefficient | `s(0, by=1)` | `s(x, by = z)` |
| Shape constraint | `constraints='monotonic_inc'`, `'monotonic_dec'`, `'convex'`, `'concave'` | not in mgcv |
| Penalty | `penalties='derivative'` (difference), `'l2'`, `'periodic'`, or a list | set by `bs` and `m` |
| Smoothing parameter | `lam=0.6` per term, or `gridsearch(X, y, lam=...)` | `method = "REML"`, or `sp = ...` to fix it |
| Selection criterion | GCV (unknown scale) or UBRE (known scale), with $\gamma = 1.4$; also <Gloss name="aic" />, <Gloss name="aicc" /> | `method = "GCV.Cp"` (default), `"REML"`, `"ML"` |
| Shrinking terms to zero | a second, `'l2'`, penalty on the term | `select = TRUE`, or `bs = "ts"` |
| Model summary | `gam.summary()` | `summary(b)` |
| Term plots | `partial_dependence(term, X, width=0.95)` | `plot(b, seWithMean = TRUE)` |
| Intervals | `confidence_intervals`, `prediction_intervals` | `predict(b, se.fit = TRUE)` |
| Posterior simulation | `sample(X, y, quantity="coef")` | `rmvn(n, coef(b), vcov(b))` with `predict(b, type = "lpmatrix")` |
| Basis and residual checks | none built in | `gam.check(b)`, `k.check(b)`, `concurvity(b)` |
| Large data | none | `bam(..., discrete = TRUE)` |

Sources: the pyGAM documentation <Cite id="pygamdocs" /> and the mgcv manual <Cite id="mgcvdocs" />. pyGAM refers to
features by column index; mgcv by name. Tensor products, cyclic, factor and `by` terms, shape constraints and
expectiles have their own notes: <NoteLink to="tensor-product-smooths">tensor-product smooths</NoteLink>,
<NoteLink to="cyclic-factor-and-by-terms">cyclic, factor and by terms</NoteLink>,
<NoteLink to="shape-constrained-additive-models">shape-constrained GAMs</NoteLink> and
<NoteLink to="expectile-generalised-additive-models">expectile GAMs</NoteLink>.

### A complete example

Two thousand hourly counts depend on the time of day (cyclic), the temperature and the day of the week. The true log
mean is $0.5 + 0.8\sin(2\pi(h - 8)/24) - 0.002(t - 18)^2 + 0.3\,[\text{weekend}]$, for hour $h$ and temperature $t$ in
°C. The model has a cyclic P-spline for the hour on $[0, 24]$, a P-spline for temperature and a factor for the day.
`gridsearch` tries 7 values of $\lambda$ for each of the three terms, $7^3 = 343$ fits, and keeps the one with the
lowest UBRE, since the Poisson scale is known.

```python
import numpy as np
from pygam import PoissonGAM, s, f

rng = np.random.default_rng(0)
n = 2000
hour = rng.uniform(0, 24, n)  # time of day, cyclic
temp = rng.uniform(-5, 30, n)  # temperature in degrees C
day = rng.integers(0, 7, n)  # day of week, a factor
eta = 0.5 + 0.8 * np.sin(2 * np.pi * (hour - 8) / 24) - 0.002 * (temp - 18) ** 2 + 0.3 * (day >= 5)
y = rng.poisson(np.exp(eta))
X = np.column_stack([hour, temp, day])

gam = PoissonGAM(s(0, basis="cp", n_splines=20, edge_knots=[0, 24]) + s(1, n_splines=20) + f(2))
grid = np.logspace(-2, 4, 7)
gam.gridsearch(X, y, lam=[grid, grid, grid], progress=False)  # 7^3 fits, UBRE
gam.summary()

# Term curves are not centred in pyGAM: compare differences, not levels.
t = np.array([[12, -5, 0], [12, 18, 0], [12, 30, 0]], dtype=float)
f1 = gam.partial_dependence(term=1, X=t)
print("f(-5) - f(18):", round(f1[0] - f1[1], 3))
print("f(30) - f(18):", round(f1[2] - f1[1], 3))
```

pyGAM also prints three warnings: one about identifiability and two saying that the p-values are too small when
smoothing parameters are estimated. Reading the output:

- **Smoothing parameters.** The chosen values, 100, 1000 and 100, lie inside the grid $10^{-2}, \dots, 10^4$. A
  choice at either end of the grid means the grid must be widened. A single array for `lam` would apply one shared
  value to every term; a list of arrays searches each term separately.
- **<NoteLink to="effective-degrees-of-freedom">Effective degrees of freedom</NoteLink>.** The hour term uses 9.1 of its
  20 coefficients, the temperature term 3.8 and the factor 4.9 of 7. None is near its cap, so the basis sizes are
  adequate. The intercept has 0.0 edf because pyGAM does not centre the smooths: the constant is absorbed into the
  spline coefficients.
- **UBRE.** pyGAM's UBRE is $D/n + 2\gamma\tau/n$ plus a constant, with $\gamma = 1.4$. Only its differences between
  fits are meaningful.
- **Temperature effect.** The true differences are $f(-5) - f(18) = -1.058$ and $f(30) - f(18) = -0.288$. The fit gives
  $-0.834$ and $-0.218$. The penalty shrinks the quadratic towards a line. The shrinkage bias is largest at the cold
  boundary, 23 degrees below the peak at 18, where the true effect is largest. The
  <NoteLink to="standard-error">standard error</NoteLink> of the first difference is 0.078 from pyGAM's frequentist
  covariance and 0.091 from the Bayesian one; neither 95% interval reaches the true value. See
  <NoteLink to="additive-model-inference-and-effective-degrees-of-freedom">GAM inference</NoteLink>.
- **p-values.** The p-values of the two smooths and the factor are tiny, and pyGAM warns that they are too small. They
  are not evidence here.

### Workflow

1. **Family and link.** Choose them from the response: counts, binary outcomes, positive skewed amounts. Check for
   overdispersion after the first fit.
2. **Terms.** A smooth for each numeric feature whose effect may be nonlinear, a factor term for each categorical
   feature, a linear term only where linearity is known, a cyclic smooth for periodic features, and tensor products
   only for interactions that the question needs.
3. **Basis sizes.** Generous: 10 to 20 for most smooths, more for features with many turning points. A larger basis
   costs computation, not accuracy, once $\lambda$ is estimated.
4. **Smoothing parameters.** REML in mgcv. In pyGAM, a per-term grid wide enough that every choice is interior.
5. **Checks.** Edf against its cap, and the k-index; residuals against the linear predictor, each feature and omitted
   features; concurvity. See <NoteLink to="additive-model-checking-and-term-selection">model checking</NoteLink>.
6. **Selection.** `select = TRUE` in mgcv, or a second penalty in pyGAM, rather than stepwise deletion by p-values
   <Cite id="marra2011" />.
7. **Interpretation.** Plot each term with its band, centred (mgcv) or as differences (pyGAM). Use predictions on the
   response scale for statements about outcomes, and posterior draws for derived quantities such as the location of a
   peak. See <NoteLink to="interpreting-generalised-additive-models">interpreting GAMs</NoteLink>.
8. **Reporting.** Give each term's edf, the criterion used for $\lambda$, and which covariance the intervals come
   from <Cite id="marra2012" />.

## Cost

A fit costs a few <NoteLink to="penalised-iteratively-reweighted-least-squares">penalised IRLS</NoteLink> iterations of
$O(np^2)$ each, for $p$ coefficients in total. A grid search multiplies this by the number of grid points, which grows
exponentially with the number of terms: 7 values for each of 5 terms is 16807 fits. mgcv's Newton optimisation of REML
typically needs tens of fits, and the number grows slowly with the number of terms <Cite id="wood2011" />. For $n$ in
the millions, mgcv's `bam` with `discrete = TRUE` discretises the covariates and fits in a fraction of the time.

## Trade-offs

- **pyGAM** fits in the Python data stack, follows the scikit-learn `fit`/`predict` interface and offers shape
  constraints and expectile regression. Its grid search scales poorly with the number of terms, its p-values are
  unreliable, it has no REML and no model checks, and its bands omit the smoothing-bias allowance.
- **mgcv** is the reference implementation: REML, centred smooths, Bayesian bands with good coverage, reduced-rank
  p-values, term selection, many families and bases, and diagnostics. It requires R.
- **Both** treat the smoothing parameters as known when computing intervals, unless asked to correct for their
  uncertainty.
