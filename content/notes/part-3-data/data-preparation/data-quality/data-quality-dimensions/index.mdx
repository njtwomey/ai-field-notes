<Definition>
**Data quality** is the degree to which a dataset satisfies the operational requirements of its consumers and downstream
learning algorithms. Following the DAMA and Wang-Strong (1996) frameworks, data quality is quantified as a vector across
six orthogonal **dimensions** <Cite id="wang1996" />:

$$
\mathbf{q}(\mathcal{D}) = \begin{bmatrix} q_{\text{accuracy}}, & q_{\text{completeness}}, & q_{\text{consistency}}, & q_{\text{validity}}, & q_{\text{uniqueness}}, & q_{\text{timeliness}} \end{bmatrix} \in [0, 1]^6.
$$

No dataset is uniformly optimal across all six dimensions. Data preparation calibrates this trade-off to match the
specific failure modes of the downstream model.
</Definition>

## Accuracy

**Accuracy** measures the degree of conformity between recorded data values and the true physical state of the
underlying real-world entities.

- **Measurement:** In practice, true ground truth is unobserved for most records. Accuracy is audited via gold-standard
  sample spot-checks, double-entry human verification, or cross-referencing authoritative external registries.
- **Machine learning impact:** 
  - *Feature noise:* Random zero-mean measurement error in continuous predictors acts as attenuation bias (shrinkage of
    regression coefficients toward zero).
  - *Label noise:* In classification, asymmetric or malicious label noise corrupts decision boundaries, reduces margin
    sharpness, and induces severe memorization in overparameterized neural networks.

## Completeness

**Completeness** measures the proportion of required attributes and entities that are populated rather than omitted or
set to null.

- **Granularity levels:**
  - *Cell completeness:* The percentage of non-null entries in feature $j$:
    
    $$
    q_{\text{cell}} = 1 - \frac{N_{\text{mis}, j}}{N}.
    $$
  - *Record completeness:* The proportion of rows in the dataset that contain zero missing values across all required
    attributes (the complete-case fraction $(1 - p)^D$).
- **Machine learning impact:** Missingness degrades effective sample size and introduces selection bias when values are
  missing at random (MAR) or missing not at random (MNAR).

## Consistency

**Consistency** asserts the absence of logical, semantic, or relational contradiction across different representations
of the same underlying facts.

- **Manifestations:**
  - *Intra-record consistency:* Inter-attribute rules within a single tuple (e.g. `Age = 5` and `Education = 'PhD'` or
    `DischargeDate < AdmissionDate`).
  - *Cross-system consistency:* Diverging customer account balances between transactional relational databases and
    analytical feature stores.
  - *Temporal consistency:* Monotonic sensor telemetry jumping backward in time due to out-of-order log arrival.
- **Machine learning impact:** Inconsistent features produce conflicting gradient updates during optimization,
  destabilizing model convergence and reducing generalization.

## Validity

**Validity** measures adherence to formal syntactic grammars, physical ranges, type definitions, and domain constraints.

### Distinguishing validity from accuracy
Validity concerns syntax and domain admissibility; accuracy concerns truth:
- A customer age recorded as `250` is **invalid** (violates human lifespan bounds).
- A customer age recorded as `45` for a real-world individual who is actually 23 is **valid syntactically**, but
  **inaccurate**.

Automated validation engines can enforce 100% validity via schema parsers and regex assertions, but validity alone
cannot guarantee factual accuracy.

## Uniqueness

**Uniqueness** asserts that every real-world entity, event, or transaction corresponds to exactly one record in the
dataset, with zero redundant duplicate rows.

- **Failure modes:** Accidental multiple billing transactions, repeated web event click logs caused by network retry
  loops, or divergent customer profiles generated by minor name variations (`"John Doe"` vs `"J. Doe"`).
- **Machine learning impact:** Duplicate records distort empirical frequencies, causing tree models and classifiers to
  overfit to repeated instances. In training-evaluation splits, duplicate instances residing across both train and test
  partitions trigger severe test-set leakage, yielding falsely optimistic evaluation metrics.

## Timeliness

**Timeliness** (encompassing *currency* and *latency*) measures the temporal freshness of the data relative to the
moment of decision-making or inference.

- **Components:**
  - *Ingestion latency:* The elapsed time between event occurrence $\tau_{\text{event}}$ and feature arrival in the
    scoring feature store $\tau_{\text{store}}$.
  - *Currency:* How recently the real-world entity state was refreshed.
- **Machine learning impact:** In non-stationary environments (e.g., fraud scoring, financial trading, ad bidding),
  stale features cause models to predict based on outdated user states, degrading conversion and revenue.

## Cleaning as an inductive modelling decision

A pervasive fallacy in applied data science is treating data cleaning as an objective, mechanical precursor to machine
learning. In modern data-centric AI, **every data cleaning operation is an inductive modeling assumption**
<Cite id="polyzotis2018" />:

1. **Outlier removal is support truncation:** Deleting extreme observations assumes the true data-generating
   distribution has thin Gaussian tails. If reality is heavy-tailed (e.g. power-law Pareto), removing outliers blinds
   the model to legitimate black swan tail risks.
2. **Imputation imposes prior distributions:** Imputing conditional means compresses feature variance and assumes
   unobserved entries match observed conditional expectations.
3. **Deduplication alters empirical base rates:** Aggressively merging near-duplicate web clicks assumes identical
   clicks are noise, discarding behavioral repetition signals.

### Workload trade-off profiles
Because cleaning resources and operational latency are bounded, teams allocate effort to the dimensions critical to
their specific domain failure modes:

| Workload Domain | Critical Dimensions | Acceptable Compromises |
| :--- | :--- | :--- |
| **Clinical Trials** | Accuracy, Completeness, Validity | Low Timeliness (months of offline auditing) |
| **Real-time Fraud Detection** | Timeliness (&lt;100ms), Validity | Moderate Completeness (accepts partial telemetry) |
| **LLM Pre-training Corpora** | Uniqueness (deduplication), Accuracy | Low Completeness (unstructured web pages naturally omit attributes) |
| **Financial Ledger Auditing** | Consistency, Uniqueness, Accuracy | High human verification overhead |

## Pitfalls

- **Maximizing quality dimensions in isolation:** Investing engineering resources to reach 99.9% completeness when the
  downstream algorithm is a gradient-boosted tree that natively handles missing values yields zero ROI compared to
  investing in label accuracy.
- **Mistaking syntactic validity for semantic accuracy:** A pipeline passing Great Expectations range checks can still
  be completely inaccurate if values are generated by a miscalibrated sensor.
- **Evaluating quality on offline dumps instead of production streams:** Measuring high quality on clean historical
  training snapshots while neglecting live streaming inference latency masks real-time degradation from training-serving
  skew.
