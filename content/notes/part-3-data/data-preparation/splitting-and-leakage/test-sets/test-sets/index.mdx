<Definition>
A **test set** is a held-out sample of labelled examples used once, at the end, to estimate how a finished model will
perform. Its size fixes the precision of that estimate. Its composition fixes which failures the estimate can reveal.
Its history of use fixes whether the estimate is still unbiased.
</Definition>

## What it is for

A test score is a measurement, and the test set is the instrument that takes it. A random 20% split yields a number, but
the number may be too noisy to separate two models, silent about a subgroup on which the model fails, or capped by label
errors. A test set that has guided many design choices also overstates performance, because the choices have fitted its
noise. Image classifiers retrained on a fresh replication of the <Gloss name="imagenet" /> test set lost 11 to 14 points
of accuracy <Cite id="recht2019" />. The notes in this section treat the test set as something designed, used sparingly
and supplemented when deployment differs from training.

## Main ideas

**Size sets resolution.** A metric computed on $n$ test examples has a <NoteLink to="standard-error">standard
error</NoteLink> of order $1/\sqrt{n}$. An accuracy near 0.9 on 1,000 examples has a 95% interval about 4 points wide.
Differences smaller than the interval cannot be read as improvements. <NoteLink to="test-set-design" /> turns a target
interval width into a required size, for the whole set and for each slice reported separately.

**Coverage and label quality set what can be seen.** A slice with ten examples yields an error estimate too noisy to act
on, so small subgroups are oversampled deliberately. Label errors in the test set
bound the accuracy that can be measured, whatever the model. Behavioural suites such as CheckList add
targeted cases a random sample would rarely contain.

**Reuse turns a test set into a training signal.** Each look at test performance that changes the next model leaks a
little information from the holdout into the model. Over many rounds the reported score drifts above the true one.
<NoteLink to="test-set-reuse" /> describes adaptive overfitting, the reusable holdout and its Thresholdout mechanism
<Cite id="dwork2015" />, and the practices that limit it: a separate validation set for tuning, submission budgets and
fresh replications.

**In-distribution scores do not predict shifted ones.** A random holdout shares the training distribution, so it cannot
show how a model behaves when sensors, sites, periods or populations change.
<NoteLink to="out-of-distribution-test-sets" /> covers synthetic corruptions (ImageNet-C), natural shifts across
domains (WILDS <Cite id="koh2021" />), natural adversarial images (ImageNet-A) and effective robustness as the way to
read the gap.
