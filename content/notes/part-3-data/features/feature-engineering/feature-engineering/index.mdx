<Definition>
**Feature engineering** is the construction of new model inputs from existing data. A
feature is a function of the raw fields, of related records or of the timestamp, chosen so that a relation the model
would struggle to learn becomes a direct input. Every feature must be computable at prediction time from data available
then.
</Definition>

## What it is for

A model learns only what its inputs and its function class allow. A linear model cannot represent the ratio of debt to
income unless that ratio is an input. A tree needs many splits to approximate a weekly cycle that one indicator encodes
directly. A customer's history of orders lives in another table and has to be summarised before any single-table model
can use it. Domingos names the features used as the most important factor in whether a learning project succeeds
<Cite id="domingos2012" />.
Bad features leak the target or cannot be computed in production.

## Main ideas

**Construct features that state a relation.** <NoteLink to="feature-construction" /> builds interactions, ratios,
differences, polynomial terms and group statistics, and says which model families need them.
<NoteLink to="domain-knowledge-features" /> encodes a known mechanism, such as a dimensionless group or a ratio with
physical meaning. <NoteLink to="feature-crosses" /> combines categorical features so that a linear model can fit their
interaction, hashing the crosses when there are too many.

**Time is a rich source of features.** <NoteLink to="date-and-time-features" /> turns a timestamp into calendar parts,
holiday and event indicators, elapsed times since or until other events, and local time in the right time zone.

**Related tables become aggregates.** <NoteLink to="relational-feature-aggregation" /> describes an entity by counts,
sums and means of its related records over time windows, computed only from records that existed at prediction time.

**Search can replace part of the craft.** <NoteLink to="automated-feature-engineering" /> applies a library of
transformations and aggregations, as in Deep Feature Synthesis <Cite id="kanter2015" />, scores the candidates by how
much they improve a model and keeps the best. With more candidates than rows, the search itself overfits unless it is
validated.

**Fixed maps compress raw signals.** <NoteLink to="descriptors-embeddings-and-reductions" /> covers
<NoteLink to="handcrafted-descriptors">hand-built descriptors</NoteLink>, frozen pretrained embeddings and unsupervised
reductions such as <Gloss name="pca" />.

**One definition, served twice.** <NoteLink to="feature-stores" /> computes each feature from a single definition and
serves it as timestamped history for training and as the latest value for prediction.
<NoteLink to="point-in-time-correctness">Point-in-time joins</NoteLink> give each training row the values known at its
own time.
