<Definition>
**Table structure** is the arrangement of values into rows and columns before any model sees them. It fixes what one
row describes, which columns are variables, and how nested or free-text values become fixed-width columns. A change of
structure changes the unit a model is trained and evaluated on.
</Definition>

## What it is for

Tabular learners take a matrix: one row per example and one column per feature. Real sources rarely deliver that matrix.
Spreadsheets spread repeated measurements across columns. Event payloads arrive as <Gloss name="json" /> with nested
objects and arrays of varying length. Tables mix numbers and categories with free text such as product titles or
clinical notes. Each source has to be reshaped, flattened or vectorised first. The choices made there decide the row
unit, the number of columns and which rows belong together, and so how the data must
later be split.

## Main ideas

**Tidy data puts one observation in each row.** In a tidy table each variable is a column, each observation a row and
each kind of observational unit its own table <Cite id="wickham2014tidy" />. The rule matches the normal forms of
relational databases <Cite id="codd1970relational" />. <NoteLink to="tidy-and-reshaped-tables" /> lists the common
messy layouts and how to repair them.

**Reshaping changes the row unit.** A pivot turns a long table into a wide one, spreading repeated episodes across
columns. A melt does the reverse. After a melt, one subject contributes many rows. A random split then puts rows of the
same subject on both sides, and the validation score overstates performance on new subjects. Reshaping is therefore a
decision about the unit of observation, and the split follows from it.

**Nested records are flattened or aggregated.** <NoteLink to="semi-structured-data" /> starts by inferring a schema
from JSON-like records. Nested objects flatten into dotted column names. Arrays either explode into extra rows, which
changes the row unit again, or are pooled into summary statistics or a set encoder, which keeps one row per record.

**Text columns become numeric blocks.** <NoteLink to="text-fields-in-tables" /> turns a free-text column into TF-IDF
weights, hashed n-gram counts or embeddings from a pretrained encoder. The block is concatenated with the other columns
(<NoteLink to="multimodal-data-layouts">early fusion</NoteLink>), or a separate text model's prediction becomes one
column (late fusion, stacking).
