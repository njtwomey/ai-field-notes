<Definition>
**Language-model evaluation benchmarks** are standardized assessment batteries designed to measure the reasoning,
factual knowledge, code generation, and agentic capabilities of large language models (LLMs). Rather than measuring
linguistic structure or perplexity, they evaluate downstream task execution across multi-subject academic exams,
multi-step grade-school mathematics, PhD-level science comprehension, and real-world GitHub software patch generation
<Cite id="hendrycks2021, cobbe2021, jimenez2024swebench" />.
</Definition>

As foundation models progressed from next-token language statistics to general-purpose reasoning agents, classical NLP
benchmarks (GLUE, SQuAD) rapidly saturated. Modern LLM benchmarks test complex multi-step reasoning, tool-use execution
in sandboxed environments, and chain-of-thought problem solving <Cite id="rein2023gpqa" />.

---

## What These Datasets Measure

Modern LLM benchmarks evaluate distinct capability dimensions:
1. **Multi-Discipline World Knowledge**: Multiple-choice domain knowledge spanning STEM, humanities, social sciences,
   and professional medicine/law (MMLU) <Cite id="hendrycks2021" />.
2. **Multi-Step Mathematical & Symbolic Reasoning**: Deriving exact numerical or algebraic answers via sequential
   step-by-step chain-of-thought derivations (GSM8K, MATH) <Cite id="cobbe2021" />.
3. **Graduate-Level Expert Reasoning (Google-Proof QA)**: Answering non-trivial PhD-level questions designed by domain
   experts such that non-expert humans cannot find the answers via web search (GPQA) <Cite id="rein2023gpqa" />.
4. **Agentic Software Engineering & Tool Interaction**: Reading real GitHub issues, navigating multi-file repositories,
   writing unified diff patches, and passing unit test suites in live Docker environments (SWE-bench)
   <Cite id="jimenez2024swebench" />.
5. **Primary Evaluation Metrics**: **Zero-shot / Few-shot Accuracy**, **Pass@1 / Pass@k**, and Elo ratings from blind
   pairwise human preference votes (Chatbot Arena) <Cite id="zheng2023judge" />.

## Detailed Benchmark Profiles

### MMLU: Massive Multitask Language Understanding (2021)

Introduced by Dan Hendrycks et al. <Cite id="hendrycks2021" />:
- **Breadth**: 57 subjects spanning elementary mathematics, US history, computer science, professional law, and clinical
  medicine.
- **Protocol**: Evaluated in 5-shot prompt settings by measuring log-likelihood probabilities across options A, B, C,
  and D.
- **Benchmark Trajectory**: GPT-3 scored $43.9\%$ (barely above the $25\%$ random guessing baseline); modern frontier
  models exceed $88\text{--}90\%$, approaching human expert baselines and driving demand for harder alternatives (e.g.
  MMLU-Pro).

### GSM8K: Multi-Step Grade School Math (2021)

Developed by OpenAI (Cobbe et al. <Cite id="cobbe2021" />):
- **Linguistic Word Problems**: 8,500 multi-step arithmetic word problems requiring $2\text{--}8$ computational steps
  (addition, subtraction, multiplication, division).
- **Chain-of-Thought Revolution**: The primary benchmark where Wei et al. demonstrated the emergence of Chain-of-Thought
  (CoT) prompting, elevating model accuracy from $18\%$ to $> 60\%$ simply by prompting the model to *"think step by
  step"*.

### GPQA: Google-Proof Graduate QA (2023)

Constructed by Rein et al. <Cite id="rein2023gpqa" /> to create a ceiling against web search memorization:
- **Expert Creation**: Questions written by domain experts with PhDs in biology, chemistry, and physics.
- **Google-Proof Design**: Every question was validated to ensure that non-expert humans with unrestricted internet
  access could not find the answer within 30 minutes ($34\%$ non-expert accuracy, versus $65\%$ expert accuracy).

### SWE-bench: End-to-End Software Engineering (2024)

Created by Jimenez et al. <Cite id="jimenez2024swebench" /> from Princeton and Chicago:
- **Real GitHub Repositories**: Pairs 2,294 historical GitHub pull requests across 12 mature Python libraries (e.g.
  `django`, `sympy`, `scikit-learn`, `pytest`).
- **Execution Validation**: Models receive the issue text and codebase, and must generate a Git patch file. The patch is
  applied in an isolated Docker container, and success is defined strictly by whether previously failing unit tests now
  pass without breaking existing regression tests.

## Choosing a Language Model Benchmark

- **Broad Multi-Subject Knowledge & Baseline Auditing**:
  - MMLU / MMLU-Pro (57 academic disciplines, multiple-choice)
- **Multi-Step Mathematical Reasoning**:
  - *Grade-school arithmetic*: GSM8K
  - *Olympiad / Competition mathematics*: MATH
- **Frontier Expert Scientific Reasoning**:
  - GPQA (Google-proof PhD biology, physics, chemistry)
- **Autonomous Agentic Software Engineering**:
  - SWE-bench (Real GitHub issues, Docker test suite execution)
- **Human Real-World Alignment & Conversational Quality**:
  - LMSYS Chatbot Arena (Crowdsourced human pairwise blind Elo)

## Known Problems and Benchmark Pitfalls

1. **Pretraining Contamination**: Because LLMs pretrain on trillions of web tokens, benchmark questions and solution
   keys frequently leak into the training corpora, converting reasoning tasks into pure memorization retrieval (see
   <NoteLink to="benchmark-contamination">benchmark contamination</NoteLink>).
2. **Multiple-Choice Formatting Artifacts**: In MMLU, models can exhibit option-letter bias (favoring token `"A"` or
   `"C"`), and small prompt modifications (e.g. changing spacing or few-shot exemplars) can swing scores by
   $5\text{--}8\%$.
3. **Goodhart's Law & Leaderboard Overfitting**: When a benchmark becomes the sole target for investor and academic
   rankings, model developers optimize prompts and synthetic training mixtures directly for the benchmark, degrading
   real-world conversational utility.
