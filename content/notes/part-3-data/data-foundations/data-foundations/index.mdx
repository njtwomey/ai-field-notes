<Definition>
**Data foundations** are the properties a dataset has before anyone cleans or models it: what kind of value each column
holds, what one row describes and which rows depend on each other, how the rows were sampled and measured, how the data
were collected, and what is recorded about their origin and permitted use. These properties decide which analyses are
valid and how the data must be split.
</Definition>

## What it is for

A model can be fitted to any matrix of numbers. Whether the result means anything depends on facts that the numbers do
not show. Averaging a column of category codes is meaningless. Rows from the same patient are not independent. A sample
of approved loans says little about rejected applicants. A label that measures health-care cost does not measure health.
A licence may forbid commercial use. This subject states these facts and their consequences, so that the later steps
of exploration, preparation and modelling start from a correct description of the data.

## Main ideas

**Scales decide permitted operations.** <NoteLink to="measurement-scales" /> sorts values into nominal, ordinal,
interval and ratio scales <Cite id="stevens1946" />, with counts, proportions, durations and sets as further types. The
scale says whether values can be ordered, subtracted or divided, and so which encodings and summaries make sense.

**The setup fixes dependence and splitting.** <NoteLink to="data-setups" /> describes independent rows, groups, panels,
sequences, bags, ranked lists, streams and censored records. <NoteLink to="unit-of-observation" /> defines what one row
describes and its grain. When rows depend on each other, the <Gloss name="ess">effective sample size</Gloss> is smaller
than the row count and a random split overstates performance.

**How rows were sampled decides what they represent.** <NoteLink to="data-generating-process" /> describes the mechanism
that produced the data, including which units were included. Selection bias
arises when inclusion depends on the quantities studied, and <NoteLink to="simpsons-paradox">Simpson's
paradox</NoteLink> shows how aggregation can reverse a relation <Cite id="simpson1951" />.
<NoteLink to="target-population" /> separates the population a model will serve from the one that was sampled.

**Recorded values are not the quantities themselves.** <NoteLink to="measurement-and-recording" /> covers measurement
error, proxy targets, censoring and coarsening, and logging. <NoteLink to="data-collection" /> covers the sources of
data and the decisions that shaped them: experimental versus logged data, <NoteLink to="selective-labels">selective
labels</NoteLink> and <NoteLink to="feedback-loops">feedback loops</NoteLink>.

**Documentation makes these facts portable.** <NoteLink to="dataset-documentation" /> records provenance, collection,
labelling, consent, licence and intended use in a datasheet <Cite id="gebru2021" />, so that a later user can judge
whether the dataset suits a new task.
