<Definition>
**Data collection** is the process by which examples enter a dataset: what is gathered, from which source, under
which decisions and in what quantity. The process fixes the population the data describe, whether the data can answer
causal questions, and which outcomes were ever observed. A model trained on the result inherits all three.
</Definition>

## What it is for

Most machine-learning data were not gathered for the model that uses them. They are found in logs and records,
bought, scraped from the web or produced by an earlier system's decisions. Each route leaves a mark. A lender observes
repayment only for approved loans. A recommender logs clicks only on items it chose to show. A deployed model can
change the behaviour it later learns from. Knowing how the data were collected tells which questions they can answer,
which corrections they need and whether more data of the same kind would help.

## Main ideas

**Sources differ in cost and value.** <NoteLink to="data-acquisition" /> compares collecting, buying and licensing,
scraping, generating and labelling data. Each source has a cost per example and a marginal value for the model, and
choosing among them is a design decision with legal as well as statistical constraints.

**Randomisation separates prediction from intervention.** <NoteLink to="observational-and-logged-data" /> distinguishes
experimental data from randomised assignment, observational data found as they happened, and logged data that record
a system's own actions with their propensities. Prediction tolerates found data. Estimating what an intervention would
do needs randomisation or strong assumptions <Cite id="bottou2013" />.

**Past decisions hide outcomes.** In <NoteLink to="selective-labels" />, outcomes are observed only for cases a past
decision let through. The labelled rows describe one arm of the decision and not the population
<Cite id="lakkaraju2017" />. Reject inference, small randomised exploration slices and careful evaluation limit the
damage.

**Deployed models shape their own data.** <NoteLink to="feedback-loops" /> describes how a model's predictions decide
what is shown, approved or recorded, so that retraining entrenches its errors. Performative prediction formalises the
effect <Cite id="perdomo2020" />. Randomising a small share of exposure keeps the data informative.

**More data helps along a curve.** <NoteLink to="learning-curves-and-sample-size" /> plots error against training-set
size. Extrapolating the curve, often a power law, estimates the value of more data. The size of the test set sets the
width of the interval around any reported score.
