<Definition>
**Data operations** are the engineering practices that store, move, version, test and serve data for machine
learning. They decide how fast data reach training, whether a past dataset can be reconstructed, whether a change
upstream is caught, and whether a deployed model receives the same features it was trained on.
</Definition>

## What it is for

In a deployed system, the model is a small part of the code. Most of the rest moves and transforms data, and much of the
technical debt of a machine-learning system accumulates there <Cite id="sculley2015" />. A loader that cannot keep
accelerators busy wastes compute. A dataset without a version makes a result irreproducible. A renamed column turns a
feature into zeros. A feature computed one way in training and another in serving degrades accuracy with no error
raised. Production systems need the same discipline for data that software engineering applies to code: formats,
versions, tests and monitors <Cite id="breck2017" />.

## Main ideas

**Formats and loaders set throughput.** <NoteLink to="data-formats-and-pipelines" /> compares row, columnar, array and
sharded record formats and the pipelines that read, decode, shuffle and batch them.
<NoteLink to="data-loading-and-shuffling" /> explains how shuffle buffers, shard order and
<NoteLink to="sequence-length-and-chunking">length bucketing</NoteLink> decide how random the order really is.
<NoteLink to="large-scale-processing" /> processes data larger than memory, out of core or across machines, with
sketches for counts and quantiles.

**Versions make data reproducible.** <NoteLink to="versioning-and-change" /> covers content-hashed snapshots and
lineage, <NoteLink to="schema-evolution">schema evolution</NoteLink> and backfills, and batch versus stream computation.

**Tests and monitors catch changes.** <NoteLink to="data-tests" /> applies unit tests to pipelines: transforms on known
inputs, join invariants, assertions that splits do not overlap, and golden samples. <NoteLink to="data-monitoring" />
watches a deployed model's inputs, missing rates, prediction distributions and label arrival, with alert thresholds.

**Training and serving must agree.** <NoteLink to="training-serving-skew" /> lists the causes of a mismatch between
training and production features: reimplemented logic, batch versus streaming values, stale caches and different
defaults. <NoteLink to="feature-freshness" /> measures how old a feature's value is when used, and how latency budgets
decide which features are precomputed.
