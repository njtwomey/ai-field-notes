## Packaging: can `aifn` be consumed outside this repo?

Not as it stands. Inside the repo it works: npm workspaces symlink `node_modules/aifn → aifn-js/core` and
`aifn-methods → aifn-js/applications`. The `exports` map (`"."` and `"./*": "./src/*/index.ts"`) resolves every
`aifn/<family>[/<module>]`, and each package imports itself through its own name. The gaps:

1. **No build output.** `exports` points at `.ts` source. All 1125 relative imports in core are extensionless
   (`'./foo'`). Neither Node's type stripping nor `tsc --rewriteRelativeImportExtensions` can consume them, so only a
   TypeScript-aware bundler (Vite, esbuild) can use the package today.
2. **No declarations and no `types` condition.** `noEmit` is set everywhere.
3. **`private: true`, version `0.0.0`, no `files`, no `license`.**
4. **Side effects.** There is no `sideEffects` field, so bundlers treat every module as side-effectful and tree-shake
   only at the export level. That is the correct, safe default: importing a module registers its primitives, and a
   second registration throws (see the comment in `aifn-lab/vite.config.ts`). The same throw is a packaging hazard,
   because two copies of `aifn` in one bundle (the site and the lab sharing a page, or two versions) fail at load. A
   real package should make registration idempotent per identity, or key the registry on a global symbol.
5. **Applications** have no `"."` export, by design: the lint forbids the root.

Recommendation, **M**:

- Add a `build` script: `tsc -p` with an emit config, `declaration: true` and `.ts` relative specifiers plus
  `rewriteRelativeImportExtensions`. That means a codemod adding extensions to 1125 imports. Alternatively, use
  tsup or Vite library mode with one entry per module.
- Add `exports` conditions `{ types, import }` pointing at `dist/`, keeping a `development` or `source` condition for
  the workspace.
- Add `files: ["dist"]`, a version, and `sideEffects` listing the registering files.

For the site alone, none of this is needed: the site can import `aifn/...` through the workspace now, as the lab does.
